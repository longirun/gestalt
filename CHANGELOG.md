- **2026-09-05 (терминология — точка отсечки):** заменён термин *watermark / «водяной знак»* на **«точка отсечки» (cutoff)** для механизма инвалидации `PortraitSnapshot` (**Р19**). Мотив: метафора watermark из stream processing (окна, late arrivals) чужеродна для Pure PG и порождала двусмысленность кальки «водяной знак». Источник: транзакционные системы / CDC / батчинг (граница включённых в слепок данных, предикат `max(system_time) > cutoff`). Синхронизированы: `06` §8.2, `14` §3/§4/§5, `13` §3, `STATUS` (Р19, Н3), `ROADMAP`.

Мотив: «сорт» читается как грейд/сортировка — провал критерия узнаваемости Р22. - **2026-09-05 (Н12/П1 закрыт):** принята модель **identity факта WORLD** → **Р23**: identity = `(owner, scope, project_id, subject_norm, predicate_norm, conditions)` — только для STATE (полный anchor); `object` — версииемое значение, в identity не входит («Java 21» vs «Java 21 LTS» — одна пропозиция, Кинч). Инвариант **≤1 ACTIVE на identity** (реляционная FD, частичный unique-индекс ловит гонки батчей). Fast path переписан как двухшаговый детерминированный дедуп (16 §4.1): identity-lookup → сравнение нормализованного object (усиление / кандидат supersession / новый факт). `conditions` — first-class поле, входит в identity: разные conditions → **sibling** — сосуществующие истины (прототип MV-register/CRDT), не ложный supersession. Custom-предикаты — та же механика, дрейф → merge в Dreaming. Принцип П2 (типизированный словарь STATE-предикатов: тип значения + каноническая форма + семантика сравнения) → 16 §2.2; остаток Н12: состав ядра, политика custom-хвоста, токен-бюджет, subject-алиасы → затем П3 → П4.
