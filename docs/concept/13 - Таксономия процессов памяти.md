# Gestalt — 13: Таксономия процессов памяти

> 2026-09-04 · Источник: закрытие нити Н1 · Статус: **канон** (**Р18**; дополнен **Р39** — регламент Dreaming и матрица владения операциями; STATUS).
> Дополняет: `06 - Концептуальный фундамент.md` §Q2 (фазы памяти), `09 - Construct.md` §4 (жизненный цикл конструкта), `10 - Проекты и радиус применимости.md` §3.4 (жизненный цикл факта).

## 1. Принцип именования

- Имена процессов — **герундии**: длительность и процесс, а не персонаж-исполнитель («кто-то делает» → «идёт процесс»).
- Каждое имя — психологический термин с **теоретической опорой**; псих-метафоры официальны в документации и разговоре.

## 2. Триада write-path

| Процесс | Каденция | Синоним | Содержание | Теория |
|---|---|---|---|---|
| **Encoding** | секунды | extraction, fast path | батч-экстракция фактов (1 LLM-вызов на батч); дедуп, усиление, surprisal-тег (**Р38**) — детерминированные (Р6) | кодирование (Тульвинг) |
| **Dreaming** | часы | consolidation, slow path, «сон» | фактовый слой WORLD: supersession, триаж противоречий, свёртка, лифт scope, ко-подтверждение, пост-мортем закрытых сессий — регламент **Р39**; осей не создаёт (Р33) | консолидация во сне |
| **Gestalting** | дни/недели | созревание (systems consolidation), формирование схем | смысловой слой PSYCHE: единственный владелец индукции осей и переводов статусов (emerging→active→drifted, Р33); position детерминирован, LLM — только именование оси (Р5); портрет | схемы Бартлетта / Пиаже; complementary learning systems (McClelland 1995) |

Триада рассказывает историю: **кодируем → спим → собираем гештальт**.
Gestalting — вершина конвейера: портрет как целостный гештальт — имя проекта замыкает конвейер.

Каденции — свойство расписания исполнения, не концепции.

### 2.1. Матрица владения операциями (**Р39**)

Каждая операция записи/обслуживания памяти имеет ровно одного владельца. Инварианта: **генеративных (LLM) точек в системе ровно четыре** — батч-экстракция (Encoding), синтез statement свёрток (Dreaming), naming осей (Gestalting), judge-батч словарей (Reconciliation) — исчерпывающее выражение Р8 («LLM только на семантических границах»); всё остальное — детерминированный код. Канал **Correction** (Р41–Р43: коррекция юзера) LLM-точек не добавляет: реплика юзера входит через обычную экстракцию Encoding, все вердикты — код.

| Операция | Владелец | Код/LLM | Опора |
|---|---|---|---|
| Экстракция фактов (батч) | Encoding | LLM | Р6/Р8 |
| Дедуп, усиление, канонизация `object` | Encoding | код | Р23/Р25, 16 §4.1 |
| Surprisal-тег (`1 − max_sim`) | Encoding | код | Р38 |
| Kill-insight: мета-факт + немедленный `retired` | fast path (мимо каденций) | код | Р32/Р33 |
| Correction WORLD: supersession-вердикт по юзер-коррекции, наследование веса | fast path (мимо каденций) | код | Р41 |
| Correction PSYCHE: evidence-строка (`source_kind=stated`, топ-вес) → пересчёт position | Encoding → пересборка слепка | код | Р41, Р5 |
| Опровержение оси юзером → `retired` (emerging: 1; active: K≥2) | Gestalting, fast path | код | Р42 |
| Supersession-вердикт | Dreaming | код | 10 §2, Р39 |
| Триаж противоречий (не-юзерских) | Dreaming | код | 10 §2 |
| Priority-флаг user-correction-кандидатов в очереди разбора | Dreaming | код | Р43 |
| Свёртка: кластеризация | Dreaming | код | Р39 |
| Свёртка: синтез statement | Dreaming | LLM (≤2 батча/прогон) | Р39 |
| Лифт scope (ко-подтверждение) | Dreaming | код | 10 §3.4, Р28 |
| Пост-мортем закрытой сессии | Dreaming | код | 10 §3.5, Р39 |
| Индукция emerging-осей, переводы статусов осей | Gestalting | код | Р33 |
| Naming оси | Gestalting | LLM | Р5 |
| Judge-батч склейки словарей | Reconciliation | LLM (батч) | Р25 |
| Смерть сессий (`closed_at`), TTL-свипы | Reconciliation | код | Р10, 10 §3.5 |
| Пересборка слепка + PREFERENCES-предикат; форс-триггер при коррекции юзера | Reconciliation (джоба Р19; single-flight lease Р10) | код | Р19, Р40, Р43 |
| Read-path (слепок, recall) | вне триады — API-слой | код (0 LLM в движке) | Р8/Р35 |

## 3. Reconciliation (фон)

Сверка вычислимого предиката с хранимым состоянием + самовосстановление (lease + backoff + poison-изоляция, Р10): материализация смерти сессий (`closed_at`), TTL-свипы, перестройка PortraitSnapshot по точке отсечки (`14`, **Р19**). Инженерный канон (reconciliation loop, controller pattern) — псих-опоры не требует и не ищет.

## 4. Read-path — вне таксономии процессов

Сборка контекста и синтез ответа — не фоновые процессы с каденциями, а **per-request API-слой**: контракт `ContextProducer` с конфигурируемыми стратегиями — snapshot-быстро / LLM-микс / точный агентный (выбор хоста: скорость vs точность vs баланс). Архитектура — Н5. Snapshot — канон (`14`, **Р19**): **v1 read-path = слепок + детерминированный WORLD-recall, без LLM**; LLM-стратегии (микс, агентный) — Н5, вне v1.

## 5. Отвергнутые кандидаты (история решения, Н1)

| Кандидат | Почему отвергнут |
|---|---|
| Deriver / Deriving (Honcho) | не псих-термин («вывод мыслей»), теоретической опоры нет |
| Perceiving | гештальт-точен, но семантически мимо: перцепция — сенсорный вход, у нас — извлечение смысла из уже полученного текста |
| Distilling | ML-ассоциация (model distillation), не психология |
| `-er`-имена (Extractor / Consolidator / Inductor) | персонажи-исполнители; канон — процессы (герундии) |
| Harmonizing (для сверочного контура) | «приведение к гармонии» не отражает сверку desired vs actual; принят инженерный канон Reconciliation |
