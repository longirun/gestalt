## 1. Принцип

PortraitSnapshot — **детерминированная сборка когнитивных схем Бартлетта для обеспечения O(1) latency** (материализованная проекция портрета, готовый текстовый блок для инжекта в системный промпт):

- **теоретическая опора (Бартлетт, 1932; van Kesteren et al., 2012 / SLIMM)**: память действует через активную пред-собранную схему (когнитивный каркас), а не через сплошной перебор следов. Слепок выступает экстернализованной кортикальной схемой агента, снимая необходимость тяжелой реконструкции на каждом шаге;
- **не источник истины**: пересобирается детерминированно из фактов и конструктов (инвариант 09 §3 — ошибка индуктора не портит пул);
- **0 LLM** на сборку и доставку (Р8: тяжёлая работа — от хранимых данных; именование осей уже выполнено в Gestalting);
- **O(1) для читателя**: латентность read-path не зависит от объёма памяти.

## 2. Состав: секции с приоритетами

| Секция | Содержимое | Входы | События, сдвигающие точку отсечки |
|---|---|---|---|
| **CRITICAL** (highest priority) | критичные факты юзера (здоровье, ограничения, жёсткие запреты) | Encoding (fast path) | запись факта |
| **CONSTRUCTS** | активные `ConstructInstance`: ось [conditions] → полюс, confidence | Gestalting — индукция, naming, переводы статусов (Р33); kill-insight — fast path (немедленный `retired`, Р32/Р33) | изменение конструктов |
| **PREFERENCES** | селекция стабилизированных `Fact/PSYCHE`: независимость K≥2 (17 §7), не поднятые в оси — новой сущности нет, материал — те же Fact | Encoding → стабилизация (порог) | переход порога подтверждений |

Урок NGT (§12.1): критичный факт обязан жить в слепке, а не в retrieval — иначе его вытеснит семантически близкий шум (их distractor-промах: поиск поднял «board games» вместо факта об инвалидности).

CRITICAL — **санкционированное WORLD-вкрапление**: критичные факты юзера (здоровье, ограничения, запреты) — юзер как объект мира, т.е. WORLD-домен (10 §3.1). Слепок шире портрета личности: CONSTRUCTS/PREFERENCES — только PSYCHE; CRITICAL — критичность важнее чистоты домена (исключение из инварианта 10 §4, мотивировано уроком NGT).

**Гранулярность (Р32): слепок материализуется на пару `(user_id, project_id)`**, для безпроектных сессий — `project_id = NULL` (дефолтный слепок). CONSTRUCTS/PREFERENCES глобальны по юзеру и дублируются между его слепками (плата — копейки: десятки проектов × ≤40 строк); CRITICAL несёт проектную часть (проектные критичные факты, 16 §5.1) — потому один слепок на юзера не собирается. Читатель всегда берёт одну готовую строку — O(1) без компоновки.

## 3. Формат и капы

- секции-префиксы (паттерн peer cards Honcho, §12.2); суммарно **≤40 строк × ≤200 симв.** (~2–4k chars);
- маркер уверенности `(unconfirmed)` при confidence < 0.8 (NGT);
- маркер свежести: точка отсечки (cutoff) и время последней пересборки;
- точные капы, структура секций, критерий попадания факта в CRITICAL — имплементационные детали → ТЗ (Н8).

## 4. Инвалидация: точка отсечки (cutoff)

Событие изменения входов **ничего не пишет** — нулевая нагрузка на write-path. Устаревание — вычислимый предикат:

```
stale(profile) : max(system_time входов секций) > cutoff слепка
```

Точка отсечки не может разойтись с реальностью (канон Reconciliation: сверка предикатом, Р10). Dirty-flag колонка — отвергнутый вариант: write-path overhead и риск дрейфа флага.

## 5. Перестройка: джоба в контуре Reconciliation

Владелец перестройки — **Reconciliation** (13 §3; не новый псих-процесс), рядом с TTL-свипами и материализацией смерти сессий:

- периодическая джоба: каждые **N минут (дефолт 10, конфигурируемо)** — скан устаревших профилей → детерминированная пересборка → точка отсечки (cutoff) обновлена;
- юзер всегда приходит на **готовый** профиль: холодного первого хода нет по построению;
- coalescing latest-wins и prewarm — следствия, не механизмы: пересбор всегда по последнему состоянию БД;
- читатель при устаревшем слепке может пересобрать синхронно (детерминированно и дёшево) — fallback, если джоба отстаёт; ожидание ограничено sync-deadline;
- исполнение по канону Р10: lease + backoff + poison-изоляция.

## 6. Read-path v1

**Слепок + детерминированный WORLD-recall** — без LLM в движке read-path (Р8; оговорка и контракт запроса — **Р35**). Бюджетная лестница из v1 исключена: LLM-стратегии `ContextProducer` (LLM-микс, агентный цикл) → Н5 — двери открыты, механизмов не строим.

**Контракт запроса WORLD-recall (Р35).** Формулировка запроса — обязанность потребителя: движок принимает `recall(query, [filters])` — текст (сырая реплика тонкого клиента или осознанный tool-call запрос агента) плюс структурированные фильтры (временной диапазон, радиус) — и всегда детерминированно санитарит вход (лемматизация, стоп-слова, entity-boost по живому словарю). Радиус дефолт — context(S); USER-радиус (кросс-проектный поиск) — явный параметр: радиус recall ≠ радиус inject (матрица видимости — про неявную сборку контекста). Возврат — Top-K фактов с провенансом (проект-источник, сессия, время); multi-hop — агентная петля tool-call'ов, не движковая фича; слабый сигнал — тишина (no-false-memory). Хост без tool-loop получает standing context (слепок + inject), а не recall.

Контракт поставки (полевые паттерны §12.6, обязательные элементы):

- **бюджет блока** — лимит символов с приоритизацией секций;
- **sync-deadline** — запрос ждёт сборку ограниченное время, отдаётся что есть (джоба делает срабатывание редким);
- **fail-open** — провал секции не роняет блок; транзиентный провал не кэшируется.
