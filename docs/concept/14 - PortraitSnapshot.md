# Gestalt — 14: PortraitSnapshot

> 2026-09-04 · Источник: закрытие нити Н3 · Статус: **канон** (**Р19**; STATUS).

## 1. Принцип

PortraitSnapshot — **материализованная проекция портрета**, готовый текстовый блок для инжекта в системный промпт:

- **не источник истины**: пересобирается детерминированно из фактов и конструктов (инвариант 09 §3 — ошибка индуктора не портит пул);
- **0 LLM** на сборку и доставку (Р8: тяжёлая работа — от хранимых данных; именование осей уже выполнено в Gestalting);
- **O(1) для читателя**: латентность read-path не зависит от объёма памяти.

## 2. Состав: секции с приоритетами

| Секция | Содержимое | Входы | Инвалидация |
|---|---|---|---|
| **CRITICAL** (highest priority) | критичные факты юзера (здоровье, ограничения, жёсткие запреты) | Encoding (fast path) | от записи факта |
| **CONSTRUCTS** | активные `ConstructInstance`: ось [conditions] → полюс, confidence | Dreaming / Gestalting | от изменения конструктов |
| **PREFERENCES** | стабильные предпочтения (прошедшие порог подтверждений) | Encoding → стабилизация | от перехода порога |

Урок NGT (§12.1): критичный факт обязан жить в слепке, а не в retrieval — иначе его вытеснит семантически близкий шум (их distractor-промах: поиск поднял «board games» вместо факта об инвалидности).

## 3. Формат и капы

- секции-префиксы (паттерн peer cards Honcho, §12.2); суммарно **≤40 строк × ≤200 симв.** (~2–4k chars);
- маркер уверенности `(unconfirmed)` при confidence < 0.8 (NGT);
- маркер свежести: watermark-версия и время последней пересборки;
- точные капы, структура секций, критерий попадания факта в CRITICAL — имплементационные детали → ТЗ (Н8).

## 4. Инвалидация: водяной знак

Событие изменения входов **ничего не пишет** — нулевая нагрузка на write-path. Устаревание — вычислимый предикат:

```
stale(profile) : max(system_time входов секций) > watermark слепка
```

Watermark не может разойтись с реальностью (канон Reconciliation: сверка предикатом, Р10). Dirty-flag колонка — отвергнутый вариант: write-path overhead и риск дрейфа флага.

## 5. Перестройка: джоба в контуре Reconciliation

Владелец перестройки — **Reconciliation** (13 §3; не новый псих-процесс), рядом с TTL-свипами и материализацией смерти сессий:

- периодическая джоба: каждые **N минут (дефолт 10, конфигурируемо)** — скан устаревших профилей → детерминированная пересборка → watermark обновлён;
- юзер всегда приходит на **готовый** профиль: холодного первого хода нет по построению;
- coalescing latest-wins и prewarm — следствия, не механизмы: пересбор всегда по последнему состоянию БД;
- читатель при устаревшем слепке может пересобрать синхронно (детерминированно и дёшево) — fallback, если джоба отстаёт; ожидание ограничено sync-deadline;
- исполнение по канону Р10: lease + backoff + poison-изоляция.

## 6. Read-path v1

**Слепок + детерминированный WORLD-recall** — без LLM в read-path (Р8). Бюджетная лестница из v1 исключена: LLM-стратегии `ContextProducer` (LLM-микс, агентный цикл) → Н5 — двери открыты, механизмов не строим.

Контракт поставки (полевые паттерны §12.6, обязательные элементы):

- **бюджет блока** — лимит символов с приоритизацией секций;
- **sync-deadline** — запрос ждёт сборку ограниченное время, отдаётся что есть (джоба делает срабатывание редким);
- **fail-open** — провал секции не роняет блок; транзиентный провал не кэшируется.
