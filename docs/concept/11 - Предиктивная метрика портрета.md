## 1. Зачем мерить

Психопортрет — гипотеза: «модель человека, собранная из диалогов, чего-то стоит». Без метрики невозможно:

1. **Отличить работающий портрет от красивого мусора.** Граф конструктов, который красиво выглядит в дашборде и ничего не улучшает — самый вероятный исход без измерения.
2. **Увидеть деградацию.** Меняем промпт экстракции, порог слияния осей, модель судьи — стало лучше или хуже? Без метрики ответ «неизвестно». Это главный риск: модель портрета поплывёт — и молча.
3. **Предъявить проверяемое «профиль работает».** Позиционирование — «предиктивный инструмент»; без цифры против бейзлайна это лозунг.

Аналогия: движок памяти без метрики — как БД без бенчмарков; любой рефакторинг вслепую.

**Почему мишень — предсказание.** Альтернативы нефальсифицируемы:

| Альтернатива | Почему нет |
|---|---|
| «Верна ли черта» | Нет ground truth о психике: спросить юзера нельзя (сам не знает / врёт / меняется) |
| «Похоже на правду» (глазами LLM-судьи) | Субъективно, невоспроизводимо, деградацию не ловит |
| «Юзер доволен продуктом» | Меряет всё сразу (LLM, UI, погоду) — вклад портрета не выделить |

У предсказания есть внешний арбитр — реальность: юзер реально ответил так-то, значит прогноз либо подтвердился, либо нет. Это превращает «качество портрета» из вкусовщины в число.

## 2. Что предсказываем

**Мишень: наблюдаемое будущее поведение юзера** — реакции, выборы, предпочтения в будущих взаимодействиях.

Не меряем: черты как таковые («насколько интроверт»), следующие токены (работа LLM), ментальные состояния (только внешне проявившееся).

Теоретическая опора — не натяжение, а собственный тест теории:

- **Келли**: конструкт — прежде всего «инструмент антиципации» (09 §1). Система конструктов существует, чтобы предвосхищать события.
- **Деннет**: интенциональная позиция — модель юзера оправдана ровно настолько, насколько улучшает предсказание его поведения (06 §6). Портрет = рабочая гипотеза, поведение = эксперимент.

**Два уровня ценности движка — разводить:**

- **WORLD-recall**: агент помнит факты и договорённости → не переспрашивает, не ошибается. Это не предсказание юзера — просто хорошая память.
- **PSYCHE-предсказание**: агент попадает в реакцию юзера через модель его осей.

Научный риск (и предмет метрики) — PSYCHE-компонент. Golden-набор обязан **изолировать вклад портрета**, а не мерить «всё вместе».

## 3. Методология: парный A/B-эксперимент на срезе времени

Один эксперимент, повторённый на многих точках:

1. **Материал**: реальные логи (живой стенд, ~24.8k выводов Honcho).
   - **Filler-инвариант (Р14)**: полезные факты — вне окна истории плеч (между фактом и точкой измерения достаточно нейтральных ходов); иначе плечо-контроль видит факт в контексте и lift занижен. Для реальных логов — проверка дистанции «факт → точка», для синтетики — конструирование с filler-вставками (по NGT, `../research/12 - Аналоги memory-проектов.md` §12.1).
2. **Разрез по времени T**:

   ```
   ──────────────── прошлое ───────────────┬──────── будущее ────────
      диалоги, факты, выборы юзера          │   следующие ходы юзера
                                             │
      портрет строится ТОЛЬКО отсюда ◄──────┘   предсказываем ТОЛЬКО сюда
   ```

   Защита от подглядывания: всё после T системе недоступно.
3. **Два плеча, отличающихся ровно одной вещью**:
   - **A**: LLM + портрет (построенный из прошлого);
   - **B**: та же LLM, те же промпты, **без портрета** (контроль).

   Одна модель, один промпт → любая разница точности = вклад портрета.
4. **Точка измерения** (пример в духе стенда): прошлое даёт конструкт «краткость ↔ детализация [в тестах] = краткость» и факт «JUnit5, TestNG отвергнут». Будущий ход: юзер пишет «напиши тесты к X». Плечо A отвечает кратко на JUnit5; плечо B — развёрнуто с TestNG. Ground truth — фактическая реакция юзера в логе. Точка засчитана плечу A.
5. **Повторение на ~100–300 точках**: `accuracy(A)` vs `accuracy(B)`, **lift = Δ**. Lift > 0 стабилен → портрет несёт информацию; lift ≈ 0 → портрет — балласт, и это измерено, а не почувствовано.
6. **Прогон в CI/testkit**: любое изменение пайплайна не должно ронять lift. Это регресс-тест качества, а не разовое исследование.

**Источники точек:**
- готовые метки — моменты, где юзер скорректировал агента («не надо план, сразу код»): LLM находит кандидатов, человек утверждает выборку (разовая работа);
- синтетические дилеммы с ответом из фактического продолжения.

**Формат сценария golden-датасета (Р14)**: типизированный jsonl — факты + filler + вопрос + `expect_keywords` + категория (стартовый формат по NGT, `../research/12 - Аналоги memory-проектов.md` §12.1); сырые прогоны и провалы коммитуются.

**Судьи**: LLM-модель, парные сравнения «чей ответ предсказал фактическую реакцию» (устоявшаяся практика: Chatbot Arena / MT-Bench). Шум компенсируется: парный дизайн, 2–3 разных судьи, калибровка на подмножестве с ручной проверкой.

## 4. Сорта точек

| Сорт | Задача | Свойства |
|---|---|---|
| **L1. Выбор** | дилемма «что юзер предпочтёт» с готовым фактом | самый чистый (двоичный, воспроизводимый) — ядро набора |
| **L2. Ответ** | сравнение целых ответов агента по фактическому продолжению диалога | ближе к продукту, шумнее |
| **L3. Реакция (онлайн)** | прескриптив = гипотеза; принятие / отклонение / «убить инсайт» = измерение | единственный живой контур, самый шумный |
| **C. Контроль** | вопрос не по теме; память должна молчать | охрана precision, обратная сторона L1/L2: leak = инъекция нерелевантного = ложная память (**Р14**) |

## 5. Анти-цели (чего не меряем)

- психометрическую «истинность» черт — Деннет отвергает;
- следующие токены юзера — это работа LLM;
- долгосрочную эволюцию личности — дрейф (09) в v2+, отдельная метрика.

## 6. Состав v1 (развилка Н2 — закрыта)

✅ Решено (2026-09-03, **Р12**): вариант **А** — метрика и прескриптивы входят в v1.

- Офлайн-контур (L1+L2, golden-набор, CI-регрессия) — обязателен в v1;
- прескриптивы — минимальная форма «канал фидбека» (kill-insight + acceptance), без отдельного UI и советчика; отдельное хранилище по Р9;
- онлайн-контур (L3) = acceptance-rate прескриптивов;
- отложено: Big-Five-проекции, полный Пиаже-цикл, repertory-grid, AA-квадрант.

## 7. Открытые вопросы

Имплементационные детали — выносятся в ТЗ (**Н8**); отдельные нити не заведены (работа не ближайшего приоритета).

- Размер и состав golden-набора: доля L1 vs L2; сколько диалогов → сколько точек (Н2 говорила о 20–50 диалогах).
- Судейский пул: какие модели, сколько судей, порог расхождения при конфликте.
- Утечка претрейна: LLM могла «знать» юзера — парный дизайн компенсирует (оба плеча одной моделью), но нужен контроль.
- Ротация точек против overfitting на golden-набор.
- Смещение данных: сейчас один юзер и один агент — нужен второй-третий источник.
