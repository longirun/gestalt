# Gestalt — матрица наблюдения и профиль агента

> 2026-09-03 · Источник: продолжение обсуждения концепции · Статус: **канон** — матрица наблюдения и Actor приняты (**Р3**; STATUS); AA-квадрант отложен (**Р12**).
> Конвенция: идеи вне карточек/ТЗ помечены `[ПРЕДЛОЖЕНО]`. Дополняет `06 - Концептуальный фундамент`.

## 1. Принятое решение

Модель участников **симметрична**: и observer, и observed — равноправные данные (атрибуты),
а не партиции хранения. Продукт v1 — квадрант **AU** (агент→юзер), архитектура держит
открытыми двери до полной матрицы.

## 2. Матрица «кто кого моделирует»

```
              observed (кого моделируют)
             человек      агент
observer   ┌──────────┬──────────┐
человек    │   UU     │   UA     │
агент      │   AU     │   AA     │
```

| Квадрант | Суть | Спрос | Дорожка |
|---|---|---|---|
| **AU** | психопортрет юзера агентами (кейс Honcho) | ядро, исходный pain | **v1** |
| **AA** | агенты помнят режимы работы друг друга → маршрутизация/делегирование в multi-agent | растущий; в Java-нише пусто (Spring AI, LangChain4j не имеют памяти об агентах) | v2, через CustomAnalyzer-путь (enterprise-крюк); «официальная дорожка vs по запросу» — открыто |
| **UU** | командная/organizational память | есть, но перегретый рынок (org memory, CRM) | не вкладываемся; работает бесплатно как побочный эффект симметрии |
| **UA** | модель агента у юзера («claude осторожен, gemini terse»); калибровка ожиданий, аналитика | нишевый | живёт в том же пуле (PSYCHE над агентом) |

До симметрии квадранту UA в модели **негде было жить** — закрыто введением Actor.

## 3. Концептуальная разница: человек vs агент в позиции observed

| Аспект | Человек | Агент (LLM) |
|---|---|---|
| Дискретность selves | непрерывная личность, дрейф | идентичность = модель + промпт + версия; смена версии — скачок |
| Механизм изменения | аккомодация: supersession-цепочки, дрейф (Пиаже) | **смена эпох**: событие model_change / config-hash → valid_time обрывается эпохой, не «переучился»; континуум Пиаже неприменим |
| Глубина портрета | идиографические конструкты (Келли) | мелкий поведенческий профиль; номотетические размерности (многословие, осторожность, аффинити к инструментам, типовые ошибки); конструкты избыточны |
| Интериорность | психика существует; портрет — инструмент над ней | нет; портрет **чисто инструментален** (Деннет) — reverse-engineering конфига |
| Чувствительность | приватность психики → RLS, consent | обратная: «психика» агента = чей-то IP (системный промпт); портрет агента может утекать промпт |
| Фидбек-луп | принятие рекомендаций = субъективное предпочтение | только объективные исходы (успех/фейл задачи) |

Би-темпоральность закрывает эпохи: портрет claude-3.7 ≠ claude-4, оба — срезы по valid_time.

## 4. Экономика токенов при профилировании агентов `[ПРЕДЛОЖЕНО]`

Проблема (зафиксировано от автора проекта): агент говорит много и быстро — посвящённый
профилированию анализ жжёт токены, а завтра смена версии — и всё сгорело.

Рабочие принципы:

1. **Пассивная двунаправленная экстракция**: факты о поведении агента извлекаются тем же
   Encoding-проходом по существующему потоку сообщений (юзер-агент), без отдельных
   LLM-вызовов. Ноль дополнительного жжения.
2. **Пиннинг эпохи**: профиль агента привязан к (agent_id, version/config-hash); при смене
   версии профиль замораживается, новый начинается с чистого valid_time.
3. **Разбор агента «через пользователя»** (гипотеза автора): профиль агента строится
   в основном из UA-взаимодействий (что и так есть в пуле). Для AA — тот же пассивный
   принцип: логи взаимодействия агентов существуют и так; посвящённый анализ — только
   для высокоценных случаев.
4. (дальше по рынку) **Общий реестр портретов агентов**: поведение агента в значительной
  мере определяется версией, не юзером → базовый портрет версии шарится между
  воркспейсами + deployment-дельта локально. Community-механика и монетизационный крюк.

## 5. Следствия для доменной модели (уточняют Дизайн-заметки и 05)

1. **Actor** `{ id, kind: PERSON | AGENT, ... }` — единая сущность участника.
2. **observed — явный атрибут факта** (как observer). Больше не «неявный юзер воркспейса».
3. **Партиция и RLS — по воркспейсу (tenant), не по observed**.
   ⚠ Поправка к Дизайн-заметкам §3 (там партиция по user_id): при AA один tenant владеет
   портретами многих агентов — партиция по юзеру ломается. В personal-деплое workspace≈user,
   изоляция не слабеет.
   > ⚠ **Актуальность (Р11, 2026-09-03):** workspace исключён из v1; партиция/RLS — по `user_id`.
   > Рассуждение о tenant-партиции сохранено для v2+ (триггеры возврата: `10 - Проекты и радиус применимости.md` §6).
4. **Событие эпохи** для агентов (`model_change`) — отдельный тип события, не supersession.
5. Domain PSYCHE применим к агенту, но с ограниченной глубиной (см. §3): без конструктов,
   behavioral-размерности.
