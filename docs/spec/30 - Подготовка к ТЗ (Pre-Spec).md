## 1. Мета-промпт для генерации ТЗ 

**Роль:** Системный аналитик и архитектор (Gestalt).
**Задача:** Превратить утверждённый концептуальный канон (`docs/concept`) и реестр решений `STATUS.md` в строгое техническое задание (ТЗ) на языке Java 21.

**Рамки и архитектура:** Система памяти для ИИ-агентов. Глоссарий канонический. Технологический стек: Java 21, чистый PostgreSQL (Pure PG) + pgvector (реляционная графовая структура на CTE). Упаковка ядра — zero-framework (Р17).

**ПРАВИЛА ГЕНЕРАЦИИ ТЗ:**
1. **Форматирование:** Каждое требование имеет формат `REQ-<модуль>-<NNN>` + метка источника `[Р#n]`.
2. **EARS-шаблон:** Форма требований — «Когда <условие>, система должна <наблюдаемое поведение>».
3. **Строго по канону:** Запрещено придумывать собственные алгоритмы или сущности. Вся логика должна строго опираться на весь массив документов канона (включая, но не ограничиваясь матрицей владения операциями из 13 §2.1).
4. **Актуальный словарь:** Использовать только терминологию из канонического глоссария (06 §8.1) и таксономии (13).
5. **Java-API:** Описывай как сигнатуры портов (interface), без реализации.

**ТРЕБУЕМАЯ СТРУКТУРА ДОКУМЕНТА ТЗ:**
1. Область действия и Глоссарий
2. Доменная модель (`Fact`, `Construct`, `PortraitSnapshot`)
3. Функциональные требования (в формате EARS)
4. Алгоритмы процессов памяти (Encoding, Dreaming, Gestalting, Reconciliation)
5. Модель данных (Pure PG + векторы)
6. Java API/SPI (Порты ядра и контракты для плагинов/стартеров)
7. NFR (Производительность слепка О(1), наблюдаемость)
8. Стратегия тестирования (Golden-датасет, Р36)
9. Открытые вопросы
