# Gestalt — 33: Протокол разметки живых точек (Р45)

> 2026-09-14 · Статус: **спецификация для разработчика (канон механики разметки)** · Решение: **Р45** — уточнение §3.2 спеки 28 и W-механики плана 31 §3. Решение владельца 2026-09-14: протокол — отдельной спекой (сверх рекомендации ревью «держать в плане 31 до E6»); содержание анализа и ревью (GO) от 2026-09-14 поглощено. Словарь развилок `forkType` открыт до планки 15 стабильных живых точек (§6); заморозка и перенос положений в 28 — единым пулом по итогам E6.

## 1. Назначение и рамка

Формализует превращение реплик живого лога в экзаменационные билеты — тройку «вопрос — истина — окно»: разметка из «литературного творчества» LLM становится инженерным протоколом проекции. Закрывает методологическую угрозу тезис-чека E6: невозможность обвинить авторов в подгонке синтетических вопросов под специфику экстрактора (циркулярность Synthetic Probes — план 31 §6.3).

Рамка:
- применяется к **живым** материалам (L1- и C-точки);
- **E2-PC (LongMemEval) — исключение**: вопросы сформулированы авторами бенчмарка, спан-инварианты скипаются (§4);
- канон-основания: спека 28 §3.2 (точка = билет, W-требование), план 31 §3 (W-механика, константы прибора).

## 2. Разводка: стратегия поиска vs форма записи

Обратный проход («с конца»: паттерн будущего → выводимость из префикса → развилка M) **не заменяется** — это стратегия генерации кандидатов: живой лог почти без decision-forks (план 31 §8), перебор вперёд дорог и малопродуктивен. Настоящий протокол — форма записи найденного: анкета + инварианты + деривация проверок кодом. Слои компонуются, а не конкурируют:

| Слой | Вопрос | Инструмент |
|---|---|---|
| Поиск кандидатов | где развилка? | обратный проход (план 31 §3): человек или LLM-generator |
| Фиксация кандидата | чем точка является? | настоящий протокол: спаны + маркировка (§3) |
| Отсев | валидна ли точка? | инварианты кодом (§4) + adjudicator (§5) |

«Операция 1 — выбрать M» (§3) — результат обратного поиска, не перебор вперёд.

## 3. П1. Билет = проекция лога: три операции

Ни один токен, попадающий в вопрос/истину/проверки, не генерируется. Анкету заполняет и человек, и LLM — протокол один.

1. **Выбрать M** — позицию развилки из словаря типов (§6); для C-точек — реплика, по которой память должна молчать.
2. **Вырезать verbatim-спаны** — значения полей билета; отдельных span-полей поверх `trigger`/`truth` не вводим: раз переформулировка запрещена (ниже, Р1), вырезанный спан и есть значение поля. Цитата = текст + **анкер** (id реплики-носителя), иначе доказательство происхождения неполно:
   - `trigger` — спан реплики M (для простынь — короче реплики); анкер — сам M (`sourceMessageId`, отдельного поля не требуется);
   - `truth` — спан будущего лога (одна решающая цитата; нескольких цитат на точку не вводим до реальной потребности): любой verbatim-фрагмент, включая код, параметры CLI, имена созданных/отредактированных файлов (невербальная истина — выбор фиксируется действием, не словами); анкер — новое поле `truthMessageId`; у C-точек истины нет вовсе (оба поля отсутствуют), у LME — текст есть (gt бенчмарка), якоря нет.
3. **Промаркировать:** `forkType` (§6), тип события истины (выбор / действие / принятие / откат), альтернативы развилки, каноническая ветвь.

Деривация кодом (0 LLM):
- `must` — маркеры выбранной ветви: каноническая ветвь проецируется в набор поверхностных маркеров-синонимов (ветвь `gradle` → `["gradle", "gradlew"]`); список маркеров — зона adjudicator'а (§5);
- `mustNot` — маркеры отвергнутых альтернатив; у C-точек — маркеры нерелевантных тем;
- окно = f(M, N), N — конфигурация прибора (сейчас 5): окно не «извлекается», оно чистая функция позиции; W0 = последняя реплика вне окна, слепок M-exclusive — без изменений (план 31 §3);
- слепки M/W0, W-проверка — существующая механика прибора.

Критерии формы:
- **триггер — строго verbatim** (решение Р1): переформулировка запрещена — возвращает субъективный шум и скатывается к синтетическим пробам; служебная рамка задачи («ответь на запрос юзера») живёт в arms-промпте, не в билете;
- **анафора допустима**: спан M не обязан быть самодостаточным в вакууме — плечи гарантированно получают окно N; критерий валидности спана — понятен **в связке с окном**;
- истина строго после M (причинность — инвариант И3).

## 4. П2. Инварианты, проверяемые кодом

Расширение W-проверки: миллисекунды, substring-матчинг по сырой сессии.

| # | Инвариант | Что отсекает |
|---|---|---|
| И1 | спаны verbatim найдены в якорных репликах: `trigger` ⊆ реплика M, `truth` ⊆ реплика `truthMessageId` | галлюцинации generator'а; аудит любой точки — две строки |
| И2 | все маркеры ветви (`must`, включая синонимы) отсутствуют в репликах (W0, M] | точки, меряющие attention к локальному контексту: плечо B ответит из окна (или из самого вопроса) — ничья по построению, гарантированное занижение lift |
| И3 | `truthMessageId` > M (якорь истины строго после триггера) | нарушение причинности |
| И4 | W-проверка (существует, без изменений): релевантный факт в слепке M, evidence ≤ W0 | W-требование спеки 28 §3.2 |

- границы И2: полуинтервал (W0, M] — W0 исключён (инжестируется в память — это и есть предмет измерения), M включён (ответ, содержащийся в самой реплике-вопросе, — giveaway);
- И2 — **жёсткий reject** с единым статусом `in-window` в журнале разметки (словарь вердиктов WCheck не плодим: leak/bias не разводим); причины reject маппятся на уровни диагностики спеки 28 §4.3;
- LME-точки (без `sourceSession`): спан-инварианты skip; C-точки: И1 — только по триггеру, И2 — по `mustNot`-маркерам, И3 — неприменим.
- повторы коротких подстрок (`gradle`, `10.0.0.19`) по логу инвариантам не угрожают: И1/И3 — якорные проверки реплики-носителя, не поиск по суффиксу; для И2 повтор маркера в окне — не ложное срабатывание, а сам диагностируемый дефект (маркер видим плечу B — структурная ничья). Качество самой цитаты (одиночный токен вместо решающего фрагмента) — зона adjudicator'а, кодом не проверяется.

## 5. Роли: generator → валидатор → adjudicator

1. **Generator (LLM)** заполняет анкету по обратному проходу — без требований к precision (план 31 §4).
2. **Валидатор (код)** гоняет И1–И3: мусор отсекается автоматически, adjudicator'у уходит только прошедшее валидацию.
3. **Adjudicator (человек)** во viewer'е акцептует/отклоняет и **обязательно ревьюит маркеры-синонимы ветвей**: генератору запрещено подбирать маркеры, которыми можно «играть» с инвариантом И2 (взять синоним, отсутствующий в окне).

Разводка generator ≠ adjudicator (план 31 §4) становится исполнимой механикой, а не декларацией.

## 6. Кодбук forkType

- представление: `String` в `EvalPoint`; словарь допустимых значений — файл в `eval/data/` (вне VCS до заморозки, гигиена — спека 24 §7);
- наполнение индуктивное, до 15 стабильных живых точек (решение review 2026-09-13 — план 31 §4); enum в коде — при заморозке (перенос в 28, E6);
- seed-категории project: техвыбор A-vs-B / грабли (повтор известной ошибки) / принятие правки / откат;
- `pattern` (String) — человекочитаемое пояснение, какое соглашение/грабли проверяет точка; остаётся свободным текстом.

## 7. Внедрение

1. `EvalPoint`: `trigger`/`truth` — семантика verbatim-спанов; + `forkType`; + `truthMessageId` (nullable — C-точки и LME); словарь — `eval/data/fork-types.txt`.
2. Валидатор И1–И3 (`EvalDataset`/`WCheck`): substring-аудит по сырой сессии; reject `in-window` в журнал разметки.
3. Ретроспективный прогон на архивах: 11 точек project-0911 + 7 jrestly-0911 — проверка, не режет ли И2 живой материал (до трат на добор project-v2).
4. Viewer: подсветка спанов, фиксация выделением.

Отпечатки: точки — вход датасета, `ingest_fp`/`answer_fp` не затрагиваются.

## 8. Критерии верификации (DoD)

1. Валидатор в коде; инварианты И1–И3 зафиксированы тестами.
2. Ретро-прогон архивов проведён, числа зафиксированы (план 31).
3. Журнал разметки принимает статус `in-window`; viewer оперирует спанами.

## 10. Внешние опоры (проверка «не велосипед»)

Протокол — компиляция зрелых паттернов, а не изобретение; сверки 2026-09-14 (методология LongMemEval, LOCOMO; MSC — по памяти). Карта соответствия:

| Элемент § | Prior art | Соответствие |
|---|---|---|
| Спан + анкер (`truth` ⊆ реплика `truthMessageId`) | SQuAD (answer = text + offset); attribution/groundedness (ALCE, FActScore, Rashkin et al.) | Ответ-спан с позицией в источнике — стандарт QA-разметки; источник = лог, offset = id реплики |
| Словарь `forkType` + решётка (§6) | LongMemEval: attribute ontology (164 атрибута, 5-step pipeline); LOCOMO: 5 reasoning types | Закрытая таксономия вопросов как основа бенчмарка; у нас категории выводятся индуктивно, а не задаются |
| C-точки | LME abstention; LOCOMO adversarial | Прямой аналог: вопросы-ловушки на отказ/галлюцинацию — подтверждение архитектуры C-оси (Р14) |
| Роли generator → валидатор → adjudicator (§5) | annotation science: LLM pre-annotation + human verification; психометрия: кодировщик/адъюдикатор, inter-rater reliability | Зрелый паттерн датасетостроения; 33 делает его машинно-исполнимым |
| `must`/`mustNot` + альтернативы (§3) | классическая теория тестов: item key + distractors; Evidence-Centered Design (Mislevy): claim → evidence rule → task | Билет = задача с ключом и дистракторами |
| Плечи A/B + McNemar; И2/filler-инвариант | рандомизированный контролируемый эксперимент: treatment/control, paired stats, контаминация лечения | И2 — защита от утечки лечения в контрольную группу (маркер в окне = плечо B «знает» ответ) |
| Обратная разметка: истина из будущего → вопрос (§2) | MSC (Multi-Session Chat, Xu et al. 2021): ground truth = фактическая реплика человека в поздней сессии | Ближайший аналог предиктивной рамки |

Различие (ниша, готового протокола нет): ведущие бенчмарки строятся **синтетикой вперёд** — LME компилирует историю вокруг заранее придуманного вопроса (needle-in-a-haystack), LOCOMO генерит диалоги LLM-агентами по persona + event graph с человеческой фильтрацией; оба меряют absolute accuracy фактов в логе. Синтетика LME — родственник отвергнутых Synthetic Probes (план 31 §6.3): вопрос конструируется под известный факт. Предиктивная рамка на живом логе + парный lift против контекстного контроля — комбинация, не отработанная полем; границы валидности — язык research/25.
