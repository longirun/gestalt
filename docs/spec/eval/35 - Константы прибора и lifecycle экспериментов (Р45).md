## 1. Константы конструкции прибора

- **Окно** N = 5 реплик, единое для плеч; слепок **M-exclusive** — триггерная реплика не инжестируется (сначала ответь, потом перевари).
- **Плечи:** A = базовый системный промпт + секция-дайджест слепка (`critical`/`constructs`/`preferences` → строки-стейтменты); B = тот же каркас без секции. Temperature 0. Разводка конфигов: `llm.*` — экстрактор (прибор); `llm.answer.*` с fallback на `llm.*` — отвечающая модель (объект измерения, смена не инвалидирует слепки); `llm.embedding.*` — провайдер эмбеддингов read-time селекции (наследования от `llm.*` не имеет).
- **Матчер оракулов** — языко-независимая нижняя граница: lowercase, ё→е, срез markdown, границы слов — Unicode-lookarounds `(?<![​​\p{L}\p{N}])…(?![\p{L}\p{N}])` (ASCII-only класс считал кириллицу разделителем — «тест» ⊂ «тесты»; фикс 2026-09-14). Морфология/парафразы — ярус LLM-судьи (решение 2026-09-12; `OraclesTest` документирует).
- **Изоляция материалов в одной БД:** синтетический владелец `user:lme-<qid>` + проект `lme-<qid>` на LME-точку (без этого живые USER-факты протекают — 59 фактов на smoke, Р19); живые материалы — своим owner+project. TRUNCATE при переключениях не нужен.
- **W-механика разметки «с конца» (§2.9 канона операций):** паттерн → выводимость из префикса (человек; нет → poor-log) → развилка M (нет → no-fork) → автоматическая W-проверка: факт в слепке M и max evidence ≤ W0, где **W0 = последняя реплика вне окна**, окно строго (W0, M). Вердикты: valid / in-window / lag / unknown; нет слепка ≤ W0 — insufficient grid (отложить, не reject). Точка — только там, где хороший ответ зависит от знания о юзере/проекте. Форма билета (спан-проекция, `forkType`, инварианты И1–И3) — спека 33; обратный проход — стратегия поиска кандидатов (33 §2).
- **Журнал разметки** — append-only (`marking-journal.jsonl`, ведётся viewer'ом); конструируемость = taken / (taken + rejected), причины reject маппятся на уровни диагностики недобора (28 §4.3).

## 2. Lifecycle экспериментов (решение 2026-09-13 — «вариант 2 + экономика в runs»)

Мотивация: ручные архивы при переключении материалов, невидимая экономика прогонов, файловые результаты, не переживающие clean-up.

### 2.1. Принцип: PG — источник истины

Хранилище — БД `gestalt_eval` на `:5433`: факты, слепки (`portrait_snapshots` — последний слепок на owner+project; пер-точечные `snapshots` — M/W0-пробы), чекпоинты replay, lifecycle-таблицы §2.2. Всё, что записал прибор, — в PG; json остаётся только у входов (датасеты-точки, журнал разметки — вне VCS). `out/` (answers/oracles/wcheck/snapshots/report.md) — стираемый дамп (diff/grep, кэш viewer'а); viewer и отчёт читают БД. Кэши: чекпоинт инжеста — по последней обработанной реплике; заморозка пар ответов — по `answers` в PG.

### 2.2. Схема (`gestalt_eval`)

| Таблица | Поля (суть) | Заменяет |
|---|---|---|
| `experiments` | id-slug, материал, dataset_ref, config_snapshot, `ingest_fp`, `answer_fp`, status (active/archived), note | ручные архивы и переименования |
| `runs` | experiment, stage (replay/arms/oracles/wcheck/report), status (running/done/failed/interrupted), **llm_calls, prompt_tokens, completion_tokens**, started/finished, note | `replay-qwen*.log` вперемешку |
| `answers` | experiment+point+arm, answer, model, tokens, latency_ms, cached, run_id, at | `out/answers/*.json` |
| `verdicts` | experiment+point, pass A/B, missedMust, matchedMustNot, leak, leakMarkers, at | `out/oracles.jsonl` |
| `wchecks` | experiment+point, covered, answerCovered, valid/in-window/lag/unknown, at | `out/wcheck.jsonl` |
| `snapshots` (миграция 005) | experiment+point+kind (m/w0), payload байт-в-байт, run_id, at | `out/snapshots/*.json` |

Пер-точечные слепки M/W0 каноничны в `snapshots` (payload без jsonb-нормализации); `portrait_snapshots` инжеста по-прежнему хранит последний слепок на пару owner+project.

### 2.3. Fingerprint совместимости — «продолжать или с нуля», формализовано

- **`ingest_fp`** = hash(датасет-источник + экстрактор-модель + reasoning-effort + версия extraction-промпта + батчинг) — охраняет факты/слепки/чекпоинты. Смена → **новый эксперимент**, старый archived (read-only): forReplay отказывает; создание = архивация прочих active + сброс инжеста (DELETE facts + checkpoints reset). Идентичность источника: LME — контент LongMemEval-файла, live — дескриптор среза Honcho, смешанный датасет — обе части.
- **`answer_fp`** = hash(отвечающая модель + reasoning-effort + версия arms-промпта + окно N) — охраняет answers/verdicts. Смена = перезапись ответов в том же эксперименте (новый run), слепки переиспользуются. При врезке read-time селекции digest (research/26 §5, п.2) в состав добавляются параметры селекции — embedding-модель/размерность, top-K, порог, tie-break: их смена меняет компоновку digest → сброс answers, слепки не трогает.
- **`point_fp`** = hash(answer_fp + trigger + позиция точки: сессия/сообщение) — пер-точечная валидность строк answers: правка trigger в разметке или сдвиг позиции перегенерирует одну точку, а не весь датасет; смена answer_fp инвалидирует все строки разом. Вердикт-поля (must/truth/…) не входят — это входы оракулов, а не генерации ответа.

### 2.4. Runs: независимость, резюм, удаление

- Прогоны разных экспериментов независимы (изоляция owner/project в PG + experiment_id в таблицах).
- **Обвязка стадий:** каждая стадия (replay/arms/oracles/wcheck/report) — run со статусами running→done/failed; застрявшие при старте → interrupted (`interruptStale`). Экономика (llm_calls / prompt_tokens / completion_tokens) пишется replay/arms.
- **Резюм:** прерванный/упавший run → interrupted/failed; повторный запуск той же стадии — новый run, продолжающий работу с чекпоинтов (инжест) / с существующих пар (arms). История попыток — в базе, а не в именах логов.
- **Удаление run'а — штатная операция** (решение владельца 2026-09-13): run + записанные им артефакты (не перезаписанные позже) удаляются каскадом — «неудачный прогон с конфликтными данными» не отравляет отчёты. Перезаписанные позже артефакты выживают (answers.run_id автора). Эксперимент — archive (read-only); удаление эксперимента целиком — отдельная деструктивная операция, точки/журнал при этом остаются файлами в `eval/data/`.

## 3. Методология отбора точек

Планка отсрочки (решение review 2026-09-13 — «до 15 стабильных живых точек: академизм до материала») **пройдена**: project-v3 к E6 — 28 точек (20 L1 + 8 C по протоколу 33) из 1538 реплик живого лога; после гигиены 2026-09-19 — 25 (выбраковано 7 неисполнимых/шумных, добавлено 4 с гарантированными факт-иглами, перемаркировано 3 парафраза — research/26 §2.1).

**Применяется фактически:** протокол 33 (билет-проекция, инварианты И1–И3, словарь `forkType`, журнал разметки = screening-flow) + итеративная гигиена датасета по диагнозам прогона (выбраковка неисполнимых, дифференциальный добор точек с факт-иглами).

**Не формализовано** (переход от добора «по боли» к структурной выборке): решётка категорий × развилок как рамка популяции, кодбук inclusion/exclusion, расчёт мощности (28 §4.1) как вход в добор. Пять вопросов: критерий принадлежности §2.9; структура популяции — решётка; перечисление — generator без требований к precision; суждение — кодбук, журнал = screening-flow; достаточность — мощность. Решётка выводится индуктивно открытым кодированием среза, категории называет человек, LLM — максимум generator/второй кодировщик; **роли generator ≠ adjudicator** (исполнимая механика — 33 §4). Заморозка словаря `forkType` — планка той же клаузы (33 §6: открыт до 15 стабильных живых точек, заморозка — по итогам E6); решение — по закрытию цикла E6/E7.

**Отвергнутые альтернативы** (review, подтверждено): Synthetic Probes — циркулярность (вопросы генерируются из извлечённых фактов → тестируем экстрактор на себе, «естественность будущего» §2.9 теряется); форсирование ТЗ по одному LME — против канона (тезис-чек = живой код, ворота Н8). Полный текст методологии — git-история 31 (версия 2026-09-12).
