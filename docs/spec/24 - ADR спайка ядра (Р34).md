# Gestalt — 24: ADR спайка ядра (Р34)

> 2026-09-06 · Статус: **спецификация для разработчика (канон)** · Решение: **Р34** (STATUS §1); вход данных: драфт 23 (приватный верстак, вне VCS — параметры живого среза у владельца).

## 1. Назначение и рамка

Спайк — **вертикальный срез write-path** на Java 21: `Ingest → Encoding (батч-экстракция + дедуп) → Pure PG → PortraitSnapshot`, до финализации ТЗ (Н8). Цель — не продукт, а **эмпирика для дефолтов ТЗ**. Код — временный: каталог `spike/` в репо, архивируется по завершении (bootstrap Р34).

Документ самодостаточен для старта разработки; канонические детали — по указателям §10.

## 2. Опорные решения

| Решение | Что берём в срез |
|---|---|
| **Р8** Pass-Once | сообщение читается LLM однократно (батч-амортизация); движок — 0 LLM; LLM только на границе экстракции |
| **Р17** платформа | Java 21 LTS, zero-framework: чистые SPI, виртуальные потоки, стандартная библиотека |
| **Р18** таксономия | срез покрывает **Encoding** (сек, fast path) + фоновую **Reconciliation** (джоба пересборки слепка); Dreaming/Gestalting — вне |
| **Р19** PortraitSnapshot | материализованный слепок, детерминированная сборка **0 LLM**, инвалидация cutoff, джоба Reconciliation (lease+backoff) |
| **Р23** дедуп | двухшаговый: точный (канонический ключ) + семантический; подтверждение = `reinforcement_count++`, не INSERT |
| **Р25** канонизаторы | живой словарь предикатов/subject-имён/conditions-тегов; нормализация минимальная (trim, регистр, пробелы) |
| **Р13** измерения | `domain ∈ {WORLD, PSYCHE}` (о чём) ≠ `scope ∈ {SESSION, PROJECT, USER}` (докуда); в PG — колонка `fact_domain` |
| **Р32** гранулярность | слепок на пару `(owner_id, project_id)`, безпроектный `NULL`-дефолт |
| **Р6** гибрид | judge/семантический дедуп — без LLM-суждений в синхронном пути (косинус/тршм + пороги) |

## 3. Границы среза

**Входит:** чтение живого потока (read-only), батчирование, LLM-экстракция фактов (EAV + scope/conditions), двухшаговый дедуп, схема `facts` (Pure PG 16+), сборка и чтение PortraitSnapshot, SQL-выражения Δопыт/w, измерения (латентность, токен-стоимость, split-identity, доля дедупа).

**Не входит:** read-path WORLD-recall (**Р35** — ортогонален, можно параллелить), Dreaming/Gestalting, прескриптивы, метрика/golden (**Р36**), RLS/изоляция тенантов, API-слой. Всё это — по ТЗ.

## 5. Схема данных

Таблица `facts` (канон — 16 §2.1–2.3): `id, owner_id, session_id, project_id, fact_domain, scope, kind (STATE|NARRATIVE|EVENT), subject_norm, predicate_norm, object_value, statement, conditions JSONB, valid_time, evidence JSONB, reinforcement_count, permanence, w, created_at`.

Правила:
* полный anchor (`subject + predicate + object`) обязателен только для **STATE**; exact-дедуп — только к STATE (16 §2.2–2.3);
* identity STATE-факта = `(owner_id, scope, project_id, subject_norm, predicate_norm, conditions)` — **object не входит**: новое значение того же якоря — не дубль, а событие изменения (в спайке — логируется, supersession вне среза);
* нормализация минимальная: trim, нижний регистр, схлопывание пробелов (Р25);
* индексы: exact-ключ, `pg_trgm` GIN по `subject_norm` (split-identity кандидаты), JSONB GIN по `conditions`;
* `portrait_snapshots (owner_id, project_id)` → JSONB слепка + `cutoff` (Р19/Р32).

Динамика (17 §5): опытное время = `count(DISTINCT session_id)`; пулы интерференции = `scope`; единая кривая `w = w_floor + (1 − w_floor)·e^(−λ·Δопыт)` — SQL-заготовка `002_dynamics.sql`.

## 6. Конфигурация и окружение

* **Источник:** PG-инстанция :5433, база `honcho_memory` — **только чтение** (SELECT; отдельный read-only пользователь обязателен).
* **Цель:** база `gestalt_spike` той же инстанции — вся запись только сюда (изоляция на уровне баз).
* **LLM:** внешний OpenAI-совместимый роутер (пример инстанса — RouterAI, `routerai.ru/api/v1`; провайдер-нейтрально — любой chat-completions эндпоинт); креды — `spike/local.properties` (в .gitignore) или env `LLM_API_KEY`.
* Ключи конфига — см. `local.properties.example`; шаги раннера: `fixture-batch | ingest | extract | dedup | portrait | all`.

## 8. Критерии верификации (DoD)

**А. Прогон на синтетике** (`fixtures/jrestly-day1-synthetic.jsonl`), ожидания:

| Проверка | Ожидание |
|---|---|
| конфликт email | два факта `git_email`: `a.ivanov@orpheus-corp.example` (domain WORLD, scope USER, conditions `{organization: orpheus-corp}`) и `anton@exlibris.example` (scope PROJECT / condition `project_type=personal`) |
| проектные инварианты | `(project:libx, default_branch, "main")`, `(project:libx, github_account, "dev-anton")`, `(project:libx, build_tool, "gradle")`, `(project:libx, affiliation, "personal")` |
| мусор | реплики «ок», «Гоу 1», логи сжатия, однословные опечатки → **0 фактов** |
| повторы | повторное упоминание email/ветки → `reinforcement_count++`, не INSERT |
| слепок | JSON по `(user, project)`: секция CRITICAL несёт правило разделения email; чтение O(1) без LLM |

**Б. Живой срез** (по доступу владельца): end-to-end прогон, замер: латентность чтения слепка (p50/p95), токен-стоимость батча экстракции, доля дедупа, кандидаты split-identity (trgm-скан `subject_norm` живого словаря).

**В. Выход спайка:** эмпирические дефолты → ТЗ (Н8); код `spike/` — архивация.

## 9. Риски и обязательные инженерные меры

* **Таймауты и повторы LLM-клиента** (connect + request) — обязательны: каскад ретраев экстрактора при деградации провайдера — наблюдённая патология референса (дедлайн-таймауты, тихая потеря данных). Ни один батч не теряется молча: fail-fast с журналом.
* Источник — только read-only пользователь; запись в `gestalt_spike`.
* Никаких LLM-суждений в дедупе синхронного пути (Р6): NearDup = trgm + косинус + пороги.
* Векторы (pgvector) — опционально: если embedding-провайдер недоступен, NearDup деградирует до trgm (парковка Н5).
