# 27 — Калибровка eval-каркаса на LongMemEval (Р45)

> 2026-09-13 · Статус: **калибровка измерительного прибора (E2-PC → E5)** — итоги positive control каркаса Р45 на внешнем бенчмарке; **не тезис-чек** (границы — §4). Канон — `docs/spec/eval/28` (Р45), рабочий стол — `drafts/31`; живой тезис-чек (E6) — `docs/research/26` (зарезервировано).

---

## 1. Контекст и цель

Каркас eval (replay → плечи A/B → оракулы → отчёт) перед дорогой живой разметкой (E2: труд разметчика, §2.10 плана) откалиброван на образце с известным ответом: без positive control lift = 0 живого прогона неотличим от поломки каркаса.

* **Материал:** LongMemEval (HF `xiaowu0162/longmemeval`), oracle-подвыборка, категория `single-session-user` — короткие фактические ответы о юзере, ближайший аналог W-точек. 70 вопросов категории → **63 точки** после фильтров (ответ ≤ 8 слов, лог > окна + 1). Сессии 11–13 реплик, окно N = 5.
* **Точка:** вопрос = реплика M (M-exclusive — не инжестируется), истина = gt-ответ бенчмарка, must = слова ответа. Изоляция микромиров — синтетический владелец `user:lme-<qid>` + проект `lme-<qid>`: USER-scope факты живого владельца протекали в слепки PC (найдено на smoke — 59 фактов), изоляция владельцем обязательна (Р19).
* **Разводка конфигов:** экстракция — прибор (`llm.*`), отвечающая модель — объект измерения (`llm.answer.*`, fallback `llm.*`; glm-5.3-flash, temperature 0): смена отвечающей модели не инвалидирует слепки и кэш ответов.
* Побочный продукт — референс чужой решётки (таксономия LongMemEval) перед индуктивным кодбуком живой разметки (§2.10 плана).

## 2. Замеры

### 2.1. Encoding → слепок (WCheck)

* `covered` (есть хоть один valid-факт): **63/63** — слабая метрика, подтверждает только неотказ цепи.
* `answerCovered` (каждое must gt-ответа ⊆ valid-факты, strict-подстрока): **44/63 (70%)**; лексический матчинг ≈ 76%.
* Факты: 306 valid / 214 in-window / 0 lag / 0 unknown.
* 19 непокрытых = 9 ответ-в-фактах-но-не-valid (рождение в окне — структурная ничья плеч) + 10 strict-промахов матчера (см. §3).

### 2.2. Плечи и оракулы

| метрика | значение |
|---|---|
| точек (без leak-veto) | 63 |
| pass A (память) | 52 (83%) |
| pass B (контроль) | 22 (35%) |
| **lift** | **+48 pp** |
| только A / только B | 30 / 0 |
| оба pass / оба fail | 22 / 11 |
| C-leak (veto) | 0 |

* **МакНемар exact:** рассогласованных пар 30 (b = 0, c = 30) → p = 2/2³⁰ ≈ **1,9·10⁻⁹** — lift > 0 статистически значим (α = 0,05).
* Дискриминативность: **B-only = 0** — в рамках матчера инъекция памяти не ухудшила ни один ответ.
* Экономика: полный прогон плеч — 61 новая пара (+ 2 из кэша), 8 мин; повторные прогоны — 0 LLM-вызовов (кэш ответов + чекпоинты инжеста).

### 2.3. Ручная сверка both-fail (11 точек)

* **5 форм ответа** (матчер честно промахнулся, ответ по смыслу верен): `18th` vs `18`, `February 14th` vs `Feb 14`, `55-inch` vs `55 inches`, `my sister`, `a blue Snaggletooth`.
* **5 парафраз/порядка слов:** «the sports store downtown», полная форма University of Melbourne, `over a year` vs `more than a year`, «a mix of Irish», UCLA со скобками.
* **1 настоящий encoding-miss:** скидка `10%` не извлечена вовсе (LME-726462e0).

→ реальные потери Encoding на этом материале ≈ 1/63 (1,6%); остальное — консерватизм strict-матчера, а не поломка прибора.

## 3. Матчер: решение о ярусах

* Реализация: lowercase + ё→е + срез markdown (`[*_`"`) + вхождение с границами слов — lookarounds `(?<![A-Za-z0-9])needle(?![A-Za-z0-9])`; фикс урока «18» ⊂ «18th birthday» (ложный хит подстроки).
* Эксперимент с лингвоспецифичными фолдингами (ординалы, множественное число, артикли, притяжательные) восстановил 4–5 точек, но внёс 2 необъяснённых ложных провала (подстроки буквально присутствовали) — **откачен**.
* **Решение владельца (2026-09-12):** матчер в коде — языко-независимая нижняя граница («завтра там будет по-русски»); морфология, парафразы и синонимия — LLM-судья полного яруса. Зафиксировано тестами `OraclesTest`: `numericMarkerRespectsWordBoundaries`, `morphologicalAndParaphraseMissesAreJudgeTier`.

## 4. Границы валидности

* **Не тезис-чек:** истина = gt-ответ, а не будущее лога; механика развилок §2.9 (паттерн → выводимость → развилка) на PC не воспроизводится. Калибровка прибора, не доказательство концепции.
* **C-точки отсутствуют** (категория abstention в релизе LME нет) — контроль молчания/утечек (Р14, §4.5 канона) живым прогоном не проверялся; C-leak = 0 на PC тривиален по построению.
* **Узкая категория:** single-session-user с короткими ответами; multi-session, temporal-reasoning, knowledge-update не прогонялись (отбор категорий — при необходимости, Р37).
* **Одна отвечающая модель** (объект измерения); устойчивость lift к смене модели не измерялась.
* Датасет LME вне VCS (объём/лицензия), артефакты прогона — `eval/out/` (вне VCS, гигиена — ADR 24 §7).

## 5. Вывод

Прибор откалиброван: цепь Encoding → слепок → инъекция → ответ подтверждена на чужом материале (Encoding-потери ≈ 1,6%), инъекция памяти даёт lift +48 pp (p ≈ 1,9·10⁻⁹) без единого регресса плеча B, экономика прогона дешёвая и полностью кэшируется. Каркас готов к живой разметке (E2, §2.10: индуктивная решётка → кодбук → квоты → разметка §2.9).
