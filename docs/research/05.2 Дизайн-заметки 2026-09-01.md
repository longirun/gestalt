## 1. Контекст: ограничения существующих memory-серверов

Опыт работы с пилотным стендом показал следующие архитектурные ограничения систем на базе несимметричных пар:

- семантический поиск требует пару (observer, observed) **целиком** — частичный фильтр → 422; кросс-агентский поиск невозможен без fan-out;
- у conclusions **нет метаданных** (только content / observer_id / observed_id / session_id) — атрибуция нетривиальна;
- Dreamer консолидирует в пределах одной пары — **кросс-авторские дубли не сводятся** никогда;
- изоляция агентов как фундамент — следствие SaaS-модели Honcho; для personal/team-деплоя не нужна.

Ценность текущих данных: ~24.8k выводов (workspace пилотного стенда, пара `agent→user`), пишутся по политике B-plus (единый observer + атрибуция сессиями `explicit-writes-{agent}`).

## 2. Базовый принцип `[ПРЕДЛОЖЕНО]`

**Атрибуция — данные (колонка `author`), перспектива — параметр запроса.** Не партиция хранения.

- чтение по умолчанию — весь пул пользователя (единая модель);
- `author=X` — theory-of-mind взгляд конкретного агента (психологическая концепция сохраняется как *опция*);
- `session` / `project` — карантин и аудит.

Согласуется с моделью фактов из карточки Deriver: `author` — атрибут факта, равноправный с уверенностью/интервалом.

## 3. Многопользовательность `[ПРЕДЛОЖЕНО]`

Один стенд на всех пользователей (не инстанс на юзера):

- `users` + `user_id` FK (`ON DELETE CASCADE` — удаление юзера чистит его память) — целостность;
- **RLS**: policy `USING (user_id = current_setting('app.user_id')::uuid)` — изоляция даже при баге в коде; `SET LOCAL` в транзакции;
- `PARTITION BY LIST (user_id)` — при росте (пер-юзерный HNSW-индекс, дамп/чистка юзера тривиальны);
- кросс-юзерный «global» (если понадобится) — отдельная таблица и **отдельный query-путь**, не примешивать в пер-юзерные модели.

## 4. Конвейер обработки (маппинг на карточки)

- **Deriver** — по карточке «Извлечение фактов»: сообщение → SPO-факты {субъект, предикат, объект, полярность, уверенность, провенанс, интервал действия}; почти совпадающий → обновление уверенности/интервала; противоречащий → «вытеснен» + обратная связь.
- **Dreamer — кросс-авторская консолидация** `[ПРЕДЛОЖЕНО — расширение]`:
  1. кросс-авторский дедуп/merge (lineage аккумулирует источники);
  2. противоречия — первоклассные записи с lineage на оба лагеря; актуальность по recency + ко-подтверждению, расхождение **не прячется усреднением**;
  3. кросс-авторская индукция: факты, независимо извлечённые ≥2 авторами → синтез с бустом уверенности (ко-подтверждение);
  - канон (психологический профиль) — материализованный слой поверх иммутабельного пула, пересобираемый; score = f(число независимых авторов в lineage, recency, полярность/уверенность, вытеснённость);
  - **только экстракция/переформулирование** существующих фактов — не свободная генерация; канон-факт обязан разворачиваться в исходники (lineage ≥ 1) — аксиома трассируемости, защита от галлюцинаций в профиле.
- **Gestalt-уровень — временная ось** `[ПРЕДЛОЖЕНО]`:
  - вход: канон по временным срезам + supersession-цепочки («вытеснен») — интервалы действия фактов уже дают ось времени;
  - задачи: дрейф предпочтений, циклы, паттерны поведения → психологический портрет во времени;
  - выходы **двух типов, не смешивать**:
    - *временные факты* («предпочтение сместилось A→B в марте») — дескриптив → общий пул, lineage на факты нескольких срезов;
    - *рекомендации/паттерны* («отвечает лучше на таблицы») — прескриптив, гипотеза системы → **отдельное хранилище**; попадание в общий пул = само-референсный дрейф (система читает собственные советы как факты о юзере);
  - фидбек-луп: трекинг принятия рекомендаций → мета-факты о юзере через обычный Deriver-путь («проигнорировал 5 рекомендаций по форматированию»);
  - «убить инсайт» пользователем — тоже сигнал;
  - при multi-user: гештальт-артефакты строго per-`user_id`, RLS обязателен (самый чувствительный к приватности слой).
- **Кадентность**: Deriver — секунды (рефлекс), Dreamer — часы (сон), Gestalt — дни/неделя (рефлексия).

## 5. Синергия с моделью фактов `[ПРЕДЛОЖЕНО]`

- интервал действия + «вытеснен» уже моделируют эволюцию — Gestalt-уровень **читает** их, не дублирует;
- полярность/уверенность факта + ко-подтверждение авторов → естественная формула веса в каноне;
- граф (AGE) хранит lineage/supersession — аксиома трассируемости ложится на граф, а не на jsonb.

## 6. Импорт данных с пилотного стенда (политика B-plus)

- `observer_id` → `author`; имена сессий → `session_id` (проектная гранулярность уже в них); `explicit-writes-*` → `author` + explicit-флаг; ~24.8k выводов без потерь.

## 7. Открытые вопросы

- формат канона: таблица / граф / пересобираемое представление?
- авторы-не-агенты: сам юзер как `author` явных фактов; deriver как псевдо-автор?
- Dialectic (запросный агент) — читает канон или пул+канон?

Добавляют эти заметки (в 05 отсутствует):
