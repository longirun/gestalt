# Датасет eval (Р45)

Точки — «экзаменационные билеты», собранные вручную из живого лога (ADR 28 §3.2).
Один файл — `points.jsonl` (JSON Lines, одна точка на строку). Живые выгрузки лежат
в `eval/data/` (вне VCS); сюда коммитится **только абсолютно обезличенное**
(прецедент обезличивания — `docs/research/25 §1`). Пустой файл-плейсхолдер
создаётся разметчиком, пример полей — `points.example.jsonl`.

## Поля точки

| Поле | Смысл |
|---|---|
| `id` | Уникальный идентификатор, префикс уровня: `L1-…` / `C-…` |
| `level` | `L1` — предсказание; `C` — контрольная точка (память должна молчать) |
| `sourceSession` / `sourceMessageId` | Позиция **T** в живом логе: система видит лог только до T |
| `trigger` | Запрос юзера в позиции T — на него отвечают оба плеча |
| `truth` | Что юзер реально сделал дальше (будущее лога; разметчику доступно, системе — нет) |
| `must` / `mustNot` | Машинные проверки ответа: ключевые слова / выбор по фактам. Кодовые точки — edit-rate (вид проверки `editRate`, пока не реализован) |
| `coverage` | **W-обоснование**: какой факт/конструкт слепка на момент T релевантен истине. Для C-точек — `null` |

Правила отбора: filler-инвариант Р14 (полезный факт — вне окна истории плеч);
L1-точка без W-покрытия в слепке — не точка (плечо A по построению не могло выиграть).
Побочный продукт разметки — диагностика уровней недобора (ADR 28 §4.3):
лог бедный / Encoding не извлёк / инъекция не переводится.
