# Датасет eval (Р45, спека 33)

Точки — «экзаменационные билеты», сформированные по протоколу проекции живого лога (**[`../../docs/spec/eval/33 - Протокол разметки живых точек (Р45).md`](../../docs/spec/eval/33%20-%20Протокол%20разметки%20живых%20точек%20%28Р45%29.md)** и ADR **[`../../docs/spec/eval/28 - ADR eval-каркаса (Р45).md`](../../docs/spec/eval/28%20-%20ADR%20eval-%D0%BA%D0%B0%D1%80%D0%BA%D0%B0%D1%81%D0%B0%20%28%D0%A045%29.md)**).

Сюда коммитятся **только абсолютно обезличенные датасеты** (прецедент обезличивания — `docs/research/25 §1`) и синтетика:
* `points.lme.jsonl` — датасет калибровки LongMemEval (63 точки, E2-PC);
* `points.lme.smoke.jsonl` — быстрый smoke-набор LME;
* `points.example.jsonl` — пример структуры полей.

Активный датасет для прогона настраивается через `dataset.file` в `eval/local.properties`. Живые выгрузки лога хранятся в `eval/data/` (вне VCS).

## Поля точки (`EvalPoint`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `String` | Уникальный идентификатор, префикс уровня: `L1-…` / `C-…` |
| `level` | `String` | `L1` — предсказание поведения; `C` — контрольная точка (no-false-memory: память молчит) |
| `sourceSession` | `String` | Идентификатор сессии в логе |
| `sourceMessageId` | `Long` | Позиция **T (M)** в логе: система видит лог только строго до T |
| `trigger` | `String` | Запрос юзера в позиции M — точная **подстрока (спан)** реплики M |
| `truthMessageId` | `Long?` | ID реплики-якоря в будущем лога (обязателен для L1 живой разметки; `null` для LME и C) |
| `truth` | `String` | Реальное будущее действие юзера — точный **спан** реплики `truthMessageId` |
| `forkType` | `String?` | Тип развилки из кодбука (таблица `fork_types`, спека 33 §3, миграция `sql/006`) |
| `must` / `mustNot` | `List<String>` | Детерминированные маркеры ответа: ключевые слова (семантика `Oracles.matches`, граница слова) |
| `coverage` | `String?` | **W-обоснование**: факт/конструкт слепка на момент T, релевантный истине (`null` для C) |

## Инварианты разметки (И1–И3) и валидация

Точки проверяются детерминированным спан-валидатором кодом без LLM (`SpanValidator`):
* **И1 (Спан-анкерование):** `trigger` ⊆ реплика M, `truth` ⊆ реплика `truthMessageId`. Перефразирование запрещено (`span-miss`).
* **И2 (Защита от подсказок в окне):** маркеры `must`/`mustNot` не должны встречаться в репликах видимого окна $(W0, M]$ (`in-window`). Точка должна проверять память, а не контекст.
* **И3 (Причинность):** $W0 < M < truthMessageId$ (`causality`).

Запуск аудита датасета:
```bash
./gradlew -p eval run -Pargs='validate dataset/points.live.jsonl'
```

Правила отбора: filler-инвариант Р14 (полезный факт — вне окна истории плеч);
L1-точка без W-покрытия в слепке — не точка (плечо A по построению не могло выиграть).
Побочный продукт разметки — диагностика уровней недобора (ADR 28 §4.3):
лог бедный / Encoding не извлёк / инъекция не переводится.
