## 3. Живые решения прибора (константы конструкции)

- **Хранилище:** БД `gestalt_eval` на `:5433` (факты, слепки `portrait_snapshots` + пер-точечные `snapshots`, чекпоинты replay, experiments/runs/answers/verdicts/wchecks). Кэши: чекпоинт инжеста по последней обработанной реплике; заморозка пар ответов — по `answers` в PG. `out/` (answers/oracles/wcheck/snapshots/report.md) — стираемый дамп.
- **Окно** N = 5 реплик, единое для плеч; слепок **M-exclusive** — триггерная реплика не инжестируется (сначала ответь, потом перевари).
- **Плечи:** A = базовый системный промпт + секция-дайджест слепка (critical/constructs/preferences); B = тот же каркас без секции. Temperature 0. Разводка конфигов: `llm.*` — экстрактор (прибор), `llm.answer.*` с fallback на `llm.*` — отвечающая модель (объект измерения, смена не инвалидирует слепки).
- **Матчер оракулов** — языко-независимая нижняя граница: lowercase, ё→е, срез markdown, границы слов lookarounds `(?<![A-Za-z0-9])…(?![A-Za-z0-9])`. Морфология/парафразы — ярус LLM-судьи (решение 2026-09-12; тесты `OraclesTest` документируют).
- **Изоляция материалов в одной БД:** синтетический владелец `user:lme-<qid>` + проект `lme-<qid>` на точку LME (без этого живые USER-факты протекают — 59 фактов на smoke, Р19); живые материалы — своим owner+project. TRUNCATE при переключениях больше не нужен.
- **W-механика разметки «с конца» (§2.9 канона операций):** паттерн → выводимость из префикса (человек; нет → poor-log) → развилка M (нет → no-fork) → автоматическая W-проверка: факт в слепке M и max evidence ≤ W0, где **W0 = последняя реплика вне окна**, окно строго (W0, M). Вердикты: valid / in-window / lag / unknown. Два проба на L1-точку (M и W0); нет слепка ≤ W0 — insufficient grid (отложить, не reject). Точка = только там, где хороший ответ зависит от знания о юзере/проекте. Форма билета (спан-проекция, `forkType`, инварианты И1–И3) — спека 33 (2026-09-14); обратный проход остаётся стратегией поиска, спека 33 §2.
- **Журнал разметки** — append-only (`marking-journal.jsonl`), ведётся viewer'ом; конструируемость = taken / (taken + rejected), причины reject маппятся на уровни §4.3 канона.
- **Контракт данных A/B:** `out/answers/<pointId>.{a,b}.json` `{answer, model, tokens, latencyMs, cached, at}`; `out/oracles.jsonl` `{pointId, level, a:{pass,missedMust,matchedMustNot}, b:{…}, leak, leakMarkers}`; C-leak = mustNot в ответе A → veto.

## 7. Lifecycle экспериментов (дизайн; решение 2026-09-13 — «вариант 2 + экономика в runs»)

Мотивация: 4 материала за 3 дня переключались ручными архивами; экономика прогонов нигде не видна (project остановлен по ощущению «токены сжигаются», а не по данным — замечание review); файловые результаты не переживают clean-up/rm. **PG — источник истины**: json остаётся только у входов (датасеты-точки, журнал разметки — вне VCS, как сейчас); всё, что записал прибор, — в `gestalt_eval`; `out/` деградирует до стираемого дампа (diff/grep, кэш viewer'а) — viewer и отчёт читают БД.

**Статус: реализован полностью (reader 2026-09-13, writer 2026-09-14).** Схема `sql/004_lifecycle.sql` + `sql/005_point_snapshots.sql` (experiments/runs/answers/verdicts/wchecks/snapshots, FK с ON DELETE CASCADE — удаление эксперимента каскадом, §7.3); сторы `ExperimentStore`/`RunStore`/`ResultStore`/`PointSnapshotStore`; `Fingerprints` (ingest_fp/answer_fp по §7.2); `Experiments` — lifecycle-протокол (resolveActive, forReplay: смена ingest_fp → ошибка «новый эксперимент», создание = архивация прочих active + сброс инжеста/чекпоинтов). Writer-часть: все стадии (replay/arms/oracles/wcheck/report) в обвязке runs — running→done/failed, застрявшие → interrupted (`interruptStale`), экономика llm_calls/prompt_tokens/completion_tokens пишется replay/arms; ответы/вердикты/wchecks/слепки каноничны в PG, `out/` — стираемый дамп; пер-точечные слепки M/W0 — в `snapshots` (байт-в-байт, run_id, каскад при удалении run'а); команды `runs [slug]` (история с экономикой) и `delrun <id>` (каскадное удаление run'а; перезаписанные позже артефакты выживают — answers.run_id автора). Начальное наполнение реестра (§7.4, разовая акция 2026-09-14): lme-pc — 126 answers / 63 verdicts / 63 wchecks / 126 snapshots (8 orphan-слепков отсеянных точек отфильтрованы), jrestly-0911 + project-0911 — archived. Контроль живьём: oracles 63 checked, wcheck 63 checked (0 insufficient-grid), отчёт из PG воспроизвёл калибровку (n=63, +48 pp, p≈1,9·10⁻⁹); тесты 80/80.

### 7.1. Схема (`gestalt_eval`)

| Таблица | Поля (суть) | Заменяет |
|---|---|---|
| `experiments` | id-slug, материал, dataset_ref, config_snapshot, `ingest_fp`, `answer_fp`, status (active/archived), note | ручные архивы и переименования |
| `runs` | experiment, stage (replay/arms/oracles/wcheck/report), status (running/done/failed/interrupted), **llm_calls, prompt_tokens, completion_tokens**, started/finished, note | `replay-qwen*.log` вперемешку |
| `answers` | experiment+point+arm, answer, model, tokens, latency_ms, cached, run_id, at | `out/answers/*.json` |
| `verdicts` | experiment+point, pass A/B, missedMust, matchedMustNot, leak, leakMarkers, at | `out/oracles.jsonl` |
| `wchecks` | experiment+point, covered, answerCovered, valid/in-window/lag/unknown, at | `out/wcheck.jsonl` |
| `snapshots` (005) | experiment+point+kind (m/w0), payload байт-в-байт, run_id, at | `out/snapshots/*.json` |

Пер-точечные слепки M/W0 каноничны в `snapshots` (payload без jsonb-нормализации); `portrait_snapshots` инжеста по-прежнему хранит последний слепок на owner+project; `out/snapshots/` — дамп.

### 7.2. Fingerprint совместимости — «продолжать или с нуля», формализовано

- **`ingest_fp`** = hash(датасет + экстрактор-модель + версия extraction-промпта + батчинг) — охраняет факты/слепки/чекпоинты. Смена → **новый эксперимент**, старый archived (read-only). Пример: обогащение промпта (§6.2) = эксперимент `project-v2`, re-replay с нуля, старые чекпоинты честно остаются в старом.
- **`answer_fp`** = hash(отвечающая модель + версия arms-промпта + окно N) — охраняет answers/verdicts. Смена = перезапись ответов в том же эксперименте (новый run), слепки переиспользуются.

### 7.3. Runs: независимость, резюм, удаление

- Прогоны разных экспериментов независимы (изоляция owner/project в PG + experiment_id в таблицах).
- **Резюм:** прерванный/упавший run → статус interrupted/failed; повторный запуск той же стадии — новый run, продолжающий работу с чекпоинтов (инжест) / с существующих пар (arms). История попыток сохраняется в базе, а не в именах логов.
- **Удаление run'а — штатная операция** (решение владельца 2026-09-13): run + записанные им артефакты (не перезаписанные позже) удаляются каскадом — «неудачный прогон с конфликтными данными» не отравляет отчёты, даже несмотря на историчность. Эксперимент — archive (read-only); удаление эксперимента целиком — отдельная деструктивная операция, точки/журнал при этом остаются файлами в `eval/data/`.

### 7.4. Начальное наполнение реестра (разовая акция 2026-09-14, код переноса удалён)

- `lme-pc` — первый эксперимент реестра: артефакты калибровки перенесены в PG из `out/{answers,oracles.jsonl,wcheck.jsonl}` разовой загрузкой; после этого viewer/отчёт читают PG.
- `jrestly-0911`, `project-0911` — записи в реестре со статусом archived (материал и вердикты — §2.2); точки/журналы остаются в `eval/data/archive/`.
- Далее — путь §6.1(а): `project-v2` с новым `ingest_fp`; экономика его replay видна в `runs` до и после.

### 7.5. Границы решения

- Из «варианта 3» взято только экономика в `runs`. Не взято (позже, по боли): lifecycle-CLI (`exp list/switch/archive`), миграция датасетов в PG.
- `report.md` остаётся генерируемым файлом-артефактом (из PG); research-заметки — в `docs/research/`.
