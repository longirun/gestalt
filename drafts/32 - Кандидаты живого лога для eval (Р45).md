Рабочий материал к стадии E2 (разметка): инвентаризация сессий/дней живого лога Honcho
(`honcho_memory`, localhost:5433), пригодных для живого replay. Источник — ручное
исследование 2026-09-11 (E1 закрыта, готовимся к разметке).

## Как устроен лог

- Воркспейс в Honcho один — `opencode` (21 835 сообщений, 36 сессий, 2026-05-22 → 09-11).
  Отдельного воркспейса jrestly нет: jrestly — это сессия `per-directory-opencode-jrestly-opencode`.
- Пееры: `sinyagovsky` (пользователь), `opencode` (ассистент).
- Допущение E1 «одна сессия = один день»: replay берёт сессию из `sourceSession` точек
  датасета, день — из `source.day` конфига. Датасет может содержать только сессии одного дня.

Почему золото для eval:

- Явные предпочтения: «Коммитить и добавлять теги нельзя»; где держать TODO vs ADR;
  уровень логирования info vs debug; «наша задача не менять логирование».
- Эволюция фактов (еда для dedup/реконсиляции): коммитить-или-нет → «Нет, не коммить»;
