## 1. Контекст

Этот документ содержит предварительные решения по архитектурной декомпозиции и модульному составу Gestalt, которые ранее обсуждались и «парковались» по мере утверждения концептуального ядра. Проектирование архитектуры начинается после фиксации доменной модели (Н4, Н6, Н11).

## 2. Припаркованные решения (из нити Н5)

### 2.1. Провайдер эмбеддингов
*   **Внешний зависимый сервис:** Вычисление векторов (embedding) выносится за SPI-порт, аналогично хранилищу графов (GraphStore, Р7).
*   **Реализации:** 
    *   Remote-API по умолчанию (нулевая конфигурация, обращение к внешнему LLM-провайдеру).
    *   Локальный in-JVM-модуль (ONNX int8, модели на десятки МБ) для enterprise / air-gapped инсталляций.
*   **Пиннинг модели на базу:** Векторы разных моделей математически несравнимы. Поддерживается failover только на ту же самую модель (same-model). Смена модели = полноценная миграция с пере-эмбеддингом всей базы. (Следствие Р25: пороги косинусного сходства жестко привязаны к конкретной модели).
*   **Деградация вместо отказа (Fail-open):** 
    *   Точный дедуп (exact-dedup) и навигация по anchor-путям не требуют векторов.
    *   Семантические ветки (NARRATIVE/EVENT, HNSW-insert, dense-recall) при недоступности провайдера живут очередью или деградируют до Full-Text Search (FTS). 
    *   Недоступность LLM-провайдера означает просадку полноты (recall), но не отказ системы.

### 2.2. Трансляция портрета (хвост аудита 2.6)
*   Сырые координаты осей Келли (например, `ось: академичный ↔ прагматичный, position: 0.8`) плохо воспринимаются целевыми хост-LLM. 
*   **Решение:** Вводится слой `ContextProducer` (сборка системного промпта), который отвечает за трансляцию сырых координат портрета в поведенческие директивы (например, «не предлагай экспериментальные библиотеки, используй проверенные решения»). Эта логика — часть слоя отдачи, а не модели данных.

### 2.3. Read-path API
*   Стратегии `ContextProducer`: snapshot (по Р19), LLM-микс, точный агентный.
*   Поддержка dual-path prefetch (§12.2), per-prompt инжекция и тег `_source` (§12.5), hints-аккумулятор + topics-fingerprint (§12.6).
*   Multi-signal WORLD-recall (semantic + BM25 + entity-boost, лемматизация).
*   Temporal query-side (временное намерение запроса vs valid_time фактов).

### 2.4. Внешние адаптеры ингеста
*   Агентные факты обрабатываются как first-class вход ингеста (фильтр tool_result-шума не режет агентные подтверждения действий — см. Р3).
*   Двухконтурная интеграция (§12.5) для систем, не поддерживающих встроенную память.
