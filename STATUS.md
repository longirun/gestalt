### Процесс «drafts → canon» (конвенция от 2026-09-03)

1. **Сессия обсуждения** → один файл `drafts/NN - Тема -черновик.md`; сквозная нумерация, номера не переиспользуются.
2. **Источник истины — STATUS.md**: решения (РNN) и нити (НNN) регистрируются здесь сразу по ходу сессии; остальные доки лишь ссылаются на РNN. Спорное с любым документом разрешается реестром.
3. **Кристаллизация**: когда решение «перестало дышать», файл переносится в `docs/{concept|spec|research}/` **с сохранением номера** (drafts/10 → docs/concept/10), шапка меняется на каноническую, нерешённые остатки переезжают в открытые нити; draft удаляется.
4. **Исторические доки** (весь 05.х и `docs/archive/`): читаются как источник идей, а не как истина; живое из них уже поглощено реестром решений.
5. **Гигиена реестра.** Строка Р — текущая истина + указатель, не летопись. При 3+ поправках к одному решению — кристаллизация: содержание → concept/research-док, строка переписывается набело, номер стабилен. Нити закрываются с критерием (решение / кристаллизация / отказ), не живут вечно. (конвенция от 2026-09-04)
6. **История — в CHANGELOG.** Записи «Обновление (...)» — только в `CHANGELOG.md`; STATUS — снапшот текущего состояния. (конвенция от 2026-09-04, Р21)
7. **Терминология — через фундамент.** Словарь вводится/меняется только в 06 §8 (дисциплинарный источник или заявленный бренд); остальной корпус ссылается, не изобретает. (конвенция от 2026-09-04, Р22)

## 1. Реестр принятых решений

Обозначения: Р<N> — решение; в скобках — первоисточник.

- **Р1. Переработка, не аналог.** Gestalt — вдохновлен идеей Honcho, но не порт, а устранение концептуальных дефектов.
- **Р2. Рамка когнитивного архитектора.** Три вопроса: **что** помнить (эпизодическое/семантическое/социальное — Тульвинг), **как** помнить (кодирование/консолидация/схемы — Пиаже), **кого** помнить и как узнать человека (идиографическое vs номотетическое). (06)
- **Р3. Наблюдение и атрибуция.** Пара (observer, observed) реформирована в колонку `observer` + перспективу как query-параметр; имя — `observer` (ToM-канон, миграция Honcho 1:1). Симметричный `Actor {id, kind: PERSON|AGENT}`; матрица наблюдения AU/AA/UA/UU; **v1 = AU** (агент наблюдает человека), двери к остальным квадрантам открыты. Смена версии агента = смена эпохи (событие), не supersession. (07, 05.2)
- **Р4. Идиографическое ядро + номотетические проекции.** Ядро — конструкты Келли (открытое, community); проекции (Big Five и т.п.) — enterprise-слой (v2+, монетизация). Граница монетизации совпадает с теоретической границей. (06)
- **Р5. Construct = Axis + Instance.** `ConstructAxis` (биполярная ось, переиспользуемая, иерархическая) отдельно от `ConstructInstance` (положение конкретного observed: position + conditions + confidence + evidence lineage≥2 + valid_time). Конструкт всегда привязан к человеку; WORLD-факты — не конструкты. LLM — только именование оси; position вычисляется детерминированно из evidence. (09)
- **Р6. Гибридная дисциплина приёма.** Fast path: батч-экстракция (один LLM-вызов на батч, накопление по токенам + age-flush) + детерминированный дедуп (точный + семантический по косинусу; усиление счётчиком вместо дублирования) — без LLM-суждений. Slow path («сон»): supersession, противоречия, индукция — только здесь, с lineage. Supersession меняет **статус** факта (историчность), но не подавляет retrieval: старые факты остаются reasoning-контекстом, штраф на их видимость вредит (негативный результат HippoGraph). Канон: 16 §4; реестр 12 §12.2/§12.3.
- **Р7. Pure PostgreSQL для v1.** PG 16+ / pgvector; графовые workload'ы (lineage, иерархии, supersession — на 90% мелкохоповые) — таблицы рёбер + recursive CTE + JSONB/GIN. Порт `GraphStore` SPI: CTE-реализация по умолчанию / Apache AGE опция / Neo4j enterprise-escape. AGE не блокер и не требование ядра. (сессия; независимо подтверждено `docs/research/12` §12.2)
- **Р8. Pass-once + batch-amortized** — архитектурный инвариант (NFR): сообщение не перечитывается LLM многократно; вся тяжёлая работа — от хранимых фактов, не от сырых диалогов. LLM только на семантических границах: экстракция, именование осей, judge (read-path v1 — 0 LLM **в движке**, формулировка запроса — потребитель, **Р35**; запрос-синтез — стратегия `ContextProducer` v2+, Н5). (сессия)
- **Р9. Дескриптивы ≠ прескриптивы.** Факты/выводы (WORLD/PSYCHE) и рекомендации/советы — раздельные хранилища; исключение самореференсного дрейфа системы («система советует о себе»). (05.2)
- **Р10. Архитектурные паттерны распределённой памяти.** Зафиксировать в дизайне: reconciler self-healing (lease + backoff + poison-изоляция), reinforcement-счётчик подтверждений вместо дублирования, токен-батчинг с age-flush, session-purity явных фактов, fail-closed на пустых IN-фильтрах, иерархический конфиг со снапшотом состояния, write-time fan-out наблюдателей (LLM не множится), surprisal-подсказки без LLM. Рассмотреть: компактные слепки портрета, лестницу бюджетов рассуждений. Исключить антипаттерны: недетерминированные лимиты итераций, зависимость от физического порядка строк, утечку векторов. (`docs/research/12` §12.2)
- **Р11. Workspace исключён из v1.** Иерархия `User → Project → Session → Message`; изоляция — RLS по `user_id`; tenant = деплой. Внешние идентификаторы тенантов при импорте сворачиваются в метку провенанса. Возврат сущности — по триггерам (hosted SaaS / командные проекты UU / AA / billing), ввод аддитивной миграцией; API v1 не закладывает workspace в пути. (`docs/concept/10` §6)
- **Р12. Метрика и прескриптивы в v1 (вариант А развилки Н2).** Состав v1: ядро + Construct-minimal + метрика + прескриптивы. Метрика: офлайн golden-набор (L1 выбор + L2 ответ; парный A/B на срезе времени, lift «с портретом vs без», LLM-судьи; регресс в CI) — обязательна; онлайн-контур L3 = acceptance-rate прескриптивов. Прескриптивы — минимальная форма «канал фидбека» (kill-insight + acceptance), без отдельного UI и советчика; отдельное хранилище по Р9. Отложено: Big-Five-проекции, полный Пиаже-цикл, repertory-grid, AA-квадрант. Рамка метрики: `docs/concept/11`. (сессия; Н2)
- **Р13. Разводка измерений факта: owner / domain / scope.** `owner` — чей факт (всегда юзер, из сессии); `domain ∈ {WORLD, PSYCHE}` — **о чём** факт: **вид знания, не объект** (инференс о личности = PSYCHE; наблюдаемое о мире, включая юзера как объект, = WORLD; канон границы — 10 §3.1 = 06 §8.3); онтологическая категория задаёт инвариант чистоты портрета, дефолты scope, метрику (11 §2); `scope ∈ {SESSION, PROJECT, USER}` — **докуда** факт релевантен (радиус видимости). Омонимия устранена: слово «scope» — только радиус. Routing/tier — свойство факта в сервисе, не тег в контракте агента (полевая валидация стендом, 12 §12.6). В PG-схеме колонка `fact_domain` (`DOMAIN` — keyword в PG).
- **Р14. Методика метрики — адаптация подходов NGT** (12 §12.1). Три элемента в рамку метрики (11 §3–4): (а) контрольная ось **no-false-memory** — вопросы не по теме, замер leak-rate на уровне ответа LLM: память обязана молчать, когда не нужна (инъекция нерелевантного = ложная память); (б) **filler-инвариант golden-диалогов** — полезные факты выталкиваются за окно истории нейтральными ходами, чтобы плечо-контроль физически не имело доступа и lift был чистым; (в) **формат golden-датасета** — типизированный jsonl-сценарий (факты + filler + вопрос + expect_keywords + категория); сырые прогоны и провалы коммитуются; в составе обязательны temporal- и multi-hop-точки, где спотыкаются KG-системы. Внешний арбитр — **BEAM** (10 способностей ≈ наши мишени: abstention = ось C, knowledge updates = supersession, temporal = valid_time) и SOTA-ориентир Mem0 — трек сравнимости → **Р37**.
- **Р15. Позиционирование относительно внешних платформ.** Gestalt — самостоятельная когнитивная архитектура. Перенос данных из других систем при необходимости следует реализовать через стандартные внешние адаптеры (чтение открытых форматов экспорта в модель Gestalt, требуется проработка). База знаний по рынку ведётся в реестре аналогов `docs/research/12`. (сессия) *(Дополнение из §12.7: пересечение с recall-слоями типа Mem0 — только commodity-дисциплины extraction/retrieval; ядро — идиографическая модель человека (Construct, Р4/Р5) с предиктивной метрикой (Р14) — не дублируется: их цель «что было сказано», наша — «какой человек и что он выберет».)*
- **Р16. Консолидация исследовательской базы.** Первичные рабочие черновики и разрозненные заметки консолидированы в системном реестре аналогов `docs/research/12`. Репозиторий очищен от устаревших промежуточных материалов. Ссылки в живых документах переведены на разделы реестра 12. (сессия)
- **Р17. Лицензия и платформа ядра.** Лицензия проекта — **Apache 2.0** (максимальная открытость для community и enterprise-интеграций, связка с Р4). Платформа: **Java 21 LTS**, zero-dependency / zero-framework core (чистые Java SPI контракты, виртуальные потоки Loom, стандартные механизмы concurrency и observability). Фреймворк-адаптеры (Spring Boot Starter, Micronaut) выносятся в отдельные внешние модули; доменное ядро от них изолировано. (сессия; перенос инвариантов из 01, удалён)
- **Р18. Таксономия процессов памяти.** Write-path — триада псих-процессов: **Encoding** (сек, fast path) → **Dreaming** (часы, slow path «сон») → **Gestalting** (дни, индукция схем/портрет) + фоновая **Reconciliation** (Р10). Имена — герундии с теоретической опорой; инженерные синонимы — словарь пар; Honcho-наследие снято (термины Honcho — только в реестре 12); read-path — `ContextProducer`-стратегии вне ядра (Н5; snapshot — **Р19**). Канон: `docs/concept/13 - Таксономия процессов памяти.md`. (сессия; Н1)
- **Р19. PortraitSnapshot.** Детерминированная сборка когнитивных схем Бартлетта для обеспечения O(1) latency (Р8, Бартлетт 1932, van Kesteren 2012 / SLIMM; 0 LLM). Материализованная проекция портрета — не источник истины (инвариант 09 §3), пересбор детерминированный, **0 LLM**. Состав — секции с приоритетами: **CRITICAL** (критичные факты юзера — санкционированное WORLD-вкрапление, 14 §2; highest) → **CONSTRUCTS** (активные Instance) → **PREFERENCES** (стабильные); ≤40×200, `(unconfirmed)` при conf < 0.8. Инвалидация — точка отсечки `max(system_time входов) > cutoff` (события на write-path ничего не пишут; dirty-flag отвергнут). Перестройка — периодическая джоба (дефолт 10 мин, конфигурируемо) в контуре **Reconciliation** (lease+backoff+poison, Р10): юзер всегда на готовом профиле; coalescing/prewarm — следствия, не механизмы. Read-path v1 = слепок + WORLD-recall, без LLM в движке (Р8; контракт запроса — **Р35**); бюджетная лестница и LLM-стратегии `ContextProducer` → Н5. Канон: `docs/concept/14 - PortraitSnapshot.md`. (сессия; П2; Н3)
- **Р20. Роадмап релизов.** Планы релизов описаны явно в `ROADMAP.md` (корень): v1 — состав по Р12 (ядро + Construct-minimal + метрика + прескриптивы, квадрант AU); v2 — триггерные сущности (workspace/мультиаренда, AA-квадрант, Big-Five-проекции, community-словарь осей, prospective memory, дрейф-метрика); v3 — белое пятно (состав реестром не определён; резерв под сработавшие триггеры v2, маркеры — 10 §6). Роадмап — проекция реестра решений: новые обязательства только через РNN. (сессия)
- **Р21. Разделение статуса и истории.** STATUS.md — снапшот текущего состояния (реестр, нити, следующий шаг); хронология «Обновление (...)» вынесена в `CHANGELOG.md` (новые записи сверху). Продолжение принципа гигиены (§0 п.5): STATUS — не летопись. (сессия)
- **Р22. Терминология канона.** Словарь проекта вводится разделом «Терминология» в фундаменте (06 §8): заимствованные термины — с дисциплинарным источником (психология / нейронаука / инжиниринг) и «берём / отвергаем»; имена-бренды (Dreaming, Gestalting, PSYCHE/WORLD, прескриптив, L1/L2/L3, emerging/active, AU/AA/UA/UU) — заявлены явно с дисциплинарным прототипом. Конвенция: термин канона обязан иметь источник или статус бренда; новые термины — только через 06 §8, корпус ссылается, не чеканит приватный новояз. Критерий: узнаваемость специалистом психологии или инженерии. (сессия; снимает риск самодеятельной терминологии)
- **Р23. Identity факта WORLD и условия применимости.** Для STATE (полный anchor) identity = `(owner, scope, project_id, subject_norm, predicate_norm, conditions)`; `object` — версииемое значение, в identity не входит («Java 21» vs «Java 21 LTS» — одна пропозиция). Инвариант **≤1 ACTIVE на identity** (реляционная FD; частичный unique-индекс ловит гонки батчей). Fast path — двухшаговый детерминированный дедуп (16 §4.1): identity-lookup → сравнение нормализованного object (равен → reinforcement, отличается → кандидат supersession, нет → новый факт); NARRATIVE/EVENT — семантическая ветка. `conditions` — first-class поле, входит в identity: разные conditions → **sibling** — сосуществующие истины («5432 [dev], 5433 [prod]»), не supersession (прототип MV-register/CRDT). Custom-предикаты — та же механика; словарь предикатов — эмерджентный (пустой при рождении — доменная нейтральность), конвергенция — write-time feedback, нормализация object — домен-нейтральные канонизаторы форм. Консолидация словарей — единый механизм на четыре пространства имён (оси, предикаты, subject-имена, conditions-теги) → **Р25** (16 §2.3). Источники (Р22): Кинч и ван Дейк 1978, Кодд/FD, ACT-R base-level activation, Шапиро 2011 (MV-register).
- **Р24. «Вид» (kind) вместо «сорт».** Классификатор природы факта переименован: поле `sort` → `kind`, «сорт факта» → «вид факта» (STATE/NARRATIVE/EVENT, 16 §2.2); заодно «сорта точек» → «виды точек» (L1/L2/L3, 11 §4). Мотив: «сорт» в русском читается как грейд/сортировка — провал критерия узнаваемости (Р22). Источник: родовидовое деление (Аристотель); `kind` — идиоматика enum'ов в API; семантически точный прототип sortal (класс, задающий условия тождественности) — примечанием в словаре 06 §8.2. Конвенция 06 §8.4 соблюдена: рассылка по корпусу (06, 11, 16, STATUS, drafts). (сессия)
- **Р25. Конвергенция словарей: feedback-промпт и регламент консолидации.** Словарь **кладётся** в extraction-промпт — три пространства WORLD-identity (предикаты, subject-имена, conditions-теги; Р23): мягкое предпочтение существующих («повторяй, если предметно подходит; новое — только для нового свойства») + naming-политика формы (детерминированный regex-валидатор); отбор **top-N по использованию + «ясли»** (гарантированные слоты неподтверждённых новых имён — лечение rich-get-richer); «живое» имя = ≥1 ACTIVE-факт; словарь — проекция над `facts`, не хранимая сущность. **Сигнальный каскад кандидата склейки** (кандидат = любой сигнал ≥ порога): pg_trgm (литеральный) → fingerprint ко-использования (общий subject_norm + близкий object — сильнейший, чистый SQL) → косинус pgvector (дефолт 0.85, привязка к embedding-модели; верифицирован обезличенным аудитом живой базы). **Judge-батч** — контур **Reconciliation** (техгигиена, не Dreaming): лимиты время/объём, drain-режим, вход = пара + мини-конкорданс, каноническое имя по тай-брейку (использование → возраст → лексикография), merge-миграция коллизии ACTIVE — обычный дедуп 16 §4.1; идемпотентность и провенанс — единственная новая таблица `dictionary_pairs` с UNIQUE(namespace, a, b); poison-карантин (Р10). **Канонизаторы `object` v1**: количество (число+единица) / версия (кортеж, хвостовые нули, квалификатор-класс) / путь / url / строка; каскад по форме (url → путь → версия → количество → строка); число↔версия сравнимы по числовому ядру; **принцип консервативности** — канонизатор сливает только заведомо равное, сомнительная близость → судье. - **Р27. Единая теория динамики памяти: опытное время, несгораемый минимум, единая кривая.** Затухание меряется в **опытном времени** (Δопыт = объём нового опыта интерференционного пула с `last_seen`), календарь исключён — чистая интерференция (Underwood); устаревший мир — проблема истинности → supersession; возраст — метаданные, взвешивает читатель. Единица v1 — **сессия** (грубость осознанная: ошибка только в ранжировании, минимум защищает, использование сбрасывает `last_seen`); точная единица — приоритетный вопрос v2 (чистый SQL, 0 LLM). Формула забывания = потеря **ассоциативной** доступности при сохранении **адресной** (Tulving & Pearlstone 1966; Нуркова/Гофман 2016); единая кривая: w = w_floor + (1−w_floor)·e^{−λ·Δопыт}, λ = ln2/H; **несгораемый минимум** w_floor > 0; H/w_floor по доменам (PSYCHE — длинный H, высокое дно; WORLD — короче) — дефолты → ТЗ (Н8). Применение — только ranking bias + селекция PortraitSnapshot; иммунитет: `permanence=USER_ASSERTED` / `is_critical` → w≡1. PSYCHE v1: статусы `emerging/active/drifted` (`retired` — v2), confidence по Лапласу/Knowledge Vault, гистерезис **K = 2** (дефолт v1), триаж 10 §2; непрерывная интерференция полюсов — v2. Канон: `docs/concept/17` §2/§3/§5/§7.

- **Р35. Контракт запроса read-path (замечание 2.1 аудита; драфт 21 §2).** Двусмысленность Р8 снята: «0 LLM на read-path» = **движок** не вызывает LLM; формулировка запроса — обязанность потребителя. Semantic gap реплики (анафора/дейксис, разговорная форма vs нормализованное хранилище Р23/Р25) закрывается переносом в **уже идущий инференс хоста** (tool-call), не движковым LLM: ms-обещание — про подсистему памяти (слепок O(1), recall десятки мс), end-to-end всегда содержит хост-LLM. Контракт: единый `recall(query, [filters])` без режимов + детерминированная санитария движка (лемматизация, стоп-слова, entity-boost по живому словарю Р25). **Радиус recall ≠ радиус inject**: дефолт context(S) (10 §3.3), USER-радиус — явный параметр (расширение видимости — всегда явный акт; явный retrieval — не инъекция, RLS цел; кросс-проектный лифт Dreaming — про неявный контекст, остаётся собой). Структурированные фильтры (время, радиус; механика — temporal query-side Н5); возврат — Top-K фактов с провенансом (lineage 16 §2.1); multi-hop — агентная петля tool-call'ов, не движковая фича; слабый сигнал — тишина (16 §5.2). Хосты: tool (function calling — trained-in, не prompt-discipline) / inject (standing context, запрос не нужен) / пайп (тишина; детерминированное разворачивание по Messages — v2-кандидат, проверка против буквы Р8). Канонический пример — проверочный сценарий, не источник контракта (jmix-сценарий + контр-сценарии К1–К4 — 14 §6). Антипаттерны → реестр 12: безграничный LLM-пайплайн в синхронном пути (Honcho chat), двухконтрактная дисциплина search/chat. Канон: 14 §6. (сессия)

- **Р36. Детерминированные оракулы и экономика harness'а метрики (замечание 2.8 аудита; драфт 21 §3).** Класс проверок с вердиктом **без генеративной свободы** (обобщение `expect_keywords`): кодированные выбор/ключевые слова (`must`/`must_not` по фактам точки), исполнимость кода, edit-rate по фактическим правкам юзера в продолжении. Семантика: **veto** (детерминированный провал финален — судья не спасает) + **fast-pass** (точка, решённая оракулами, судьи не требует); **edit-rate — вердикт первого класса** на кодовых L2 (есть материал правок → судья не зовётся); проверка «противоречит базе» — только по закодированным в точке фактам, NLI — вне класса. **Каркас: статистический интеграционный тест** — точка = материализованный срез (префикс лога до T + триггер + истина-продолжение + проверки; ответы плеч не замораживаются — это выход тестируемой системы); прогон = один replay-проход лога с чекпоинтами в точках (память поднимается один раз, инжест платится один раз); ассерт — «lift ≥ порог с допуском» (булева часть — C-точки: leak = fail). **Экономика:** кэш контрольного плеча B (свойство harness'а, раз на версию датасет×хост×промпт, медианный сэмпл); кэш инжеста (база чекпоинта материализуется раз на версию Encoding + embedding-модель — пороги Р25 привязаны; правки ниже Encoding = рестор, не replay); ярусы smoke (20–50 L1+C, 0 судей, на изменение пайплайна, дешёвый хост допустим) / полный (100–300, судья на L2-остатке, milestone/nightly, боевой хост); судья-эскалация (один, пул — при споре). **Позиция:** golden — вершина тест-пирамиды, приёмочный инструмент тезиса «портрет несёт информацию»; цикл разработки — тысячи дешёвых детерминированных unit-тестов ядра (следствие Р8: 0 LLM в движке → unit-testable) + компонентные LLM-тесты на центах. Порядок жизненного цикла: спайк (Р34) → **малый тезис-чек** (lift > 0 на 20–50 точках — go/no-go) → разработка → полный гейт на релизах. Testability-требования → ТЗ (Н8): форсируемость контуров (явный вызов с явным пулом, детерминированный форвард), детерминизм replay (порядок/границы батчей), ключи кэшей, пороги, состав ярусов. Канон: 11 §3; golden-формат Р14-в — поля оракулов (`must`/`must_not`, `choice`, `edits`). (сессия)

- **Р37. Внешние бенчмарки: трек сравнимости (А) + источник синтетики (Б).** Golden Р36 и публичные бенчмарки — не конкуренты, цели разные: golden — регресс-гейт на своих данных (истина = фактическое поведение юзера, числа несравнимы между системами); бенчмарки — внешняя сравнимость и планка (health-отчёт, **не CI-гейт**). Тайминг: с появлением read-path recall в разработке (спайк Р34 его не включает); экономика — общая с harness'ом Р36 (кэш инжеста, ярусы). Канон: 11 §3 (блок «Внешние бенчмарки»). (сессия; вопрос «не велосипед ли golden против тестов mem0»)

Surprisal — write-time сигнал приоритета разбора slow path (закрытие Н10(а); прототип — NGT novelty-as-importance, 12 §12.1).** Encoding детерминированно вычисляет `1 − max_sim` к ближайшему ACTIVE-факту пула — эмбеддинг `statement` уже есть (семантическая ветка дедупа, 16 §4.1), 0 LLM. Назначение — приоритет порядка в очереди разбора Dreaming (Р39): тег временный, гаснет при разборе (потреблён ближайшим прогоном); не вход w (Р27) и не retrieval-сигнал (Р30). Научная опора — салиенс-теги сна (Stickgold & Walker 2013): ставятся при кодировании, потребляются сном, деградируют ~24 ч — быстрее следов и отдельно от них (словарь 06 §8.1). Правки: 13 §2, 16 §4.1. (сессия; драфт 26)
- **Р39. Регламент Dreaming — закрытие щелей slow path (аудит триады write-path; научная валидация — Stickgold & Walker 2013 и др.).** (1) **Триггер** прогона — каденция (часы, дефолт — конфиг → ТЗ) ИЛИ очередь разбора ≥ N (симметрия с триггером Gestalting, Р33); прогон = drain очереди. (2) **Селекция** — write-time очередь разбора: промах дедупа со сменой `object` → supersession-кандидат; ко-подтверждение из независимой сессии/проекта → лифт-кандидат; масса однородных NARRATIVE/EVENT ≥ порога → свёртка-кандидат; `closed_at` → пост-мортем-кандидат; приоритет порядка — surprisal (Р38); full-scan «суточного сна» исключён (research/18 §4.3). (3) **LLM-граница** — все вердикты детерминированы кодом (триаж 10 §2; счёт независимости Р31; кластеризация свёртки 0 LLM — каскад сигналов по аналогии Р25); LLM — только синтез statement свёрток (кластер + мини-конкорданс; консервативность «опирается только на атомы»; идемпотентность), бюджет ≤2 батча/прогон. (4) **Атомы свёртки → RETIRED** (absorbed; развилка 16 §4.3 закрыта): навигация generalized_from (Р29), вне горячего набора (инвариант 16 §3.1 цел), w не пересчитывается; «понижение приоритета» отвергнуто (шум в горячем наборе). (5) **Пост-мортем закрытой сессии** (10 §3.5): инвентаризация SESSION-фактов (ко-подтверждение → лифт с реактивацией last_seen Р28 / иначе soft-гашение) → разбор сессионных supersession-кандидатов → свёртка-проверка; осей не создаёт, PSYCHE не трогает (Р33). **Матрица владения операциями + инварианта «четыре LLM-точки»** (экстракция / синтез свёрток / naming осей / judge словарей — исчерпание Р8) — 13 §2.1. Наука: двухфазный триаж сна, ложные гисты DRM → консервативность Р25 + C-точки Р14; разводка Dreaming/Gestalting — инженерная, рамка CLS; SHY — терминология без механизма (06 §8.1). Правки: 16 §4.1–4.3, 10 §3.5, 13 §2/§2.1/§6, 17 §1/§8, 06 §8.1. (сессия; драфт 26)
- **Р40. PREFERENCES: стабилизация — предикат, не событие (фикс аудита).** «Стабилизированный» Fact/PSYCHE — не событие с исполнителем, а предикат селекции при пересборке слепка (джоба Р19, контур Reconciliation): `count(DISTINCT session_id по lineage) ≥ K` (K=2, Р31) — детерминированный SQL, 0 LLM, ноль новых сущностей/статусов. Правка 14 §2 (было «Encoding → стабилизация (порог)» — исполнитель не был назван). (сессия; драфт 26)
- **Р41. Канал Correction: ручная коррекция юзера — приоритетный класс write-path, не новая дверь.** Генерализация паттерна kill-insight (Р32/Р33) с прескриптивов на факты/оси. Коррекция = кортеж `{реактивация цели (lineage), replacement?, source, PE-контекст}`; явный канал (реплика юзера) — полноценный ивент; неявный (молчаливая правка ответа агента, L3) — только накапливается как evidence/candidate, вердикт при повторении (шум: правки по тысяче причин). Механика без новых сущностей: реплика входит обычной батч-экстракцией Encoding (инвариант «четыре LLM-точки» 13 §2.1 цел), Р23 рождает supersession-кандидат write-time (смена object = событие), надгробие = сам superseded-факт (Р6). Три добавления: (1) провенанс **`source_kind: stated | behavioral | inferred` на evidence-строке** (не на Fact — факт опирается на свидетельства разных видов; observer остаётся агентом, Р3 цел; веса: WORLD `stated` > `inferred`, PSYCHE `stated` — топ-вес, `behavioral` — независимый равноправный сигнал; read-path честность «ты говорил» vs «я заметил»; числа → ТЗ, Н8); (2) приоритетный вердикт мимо каденций: WORLD — supersession-вердикт кодом немедленно, PSYCHE — evidence-строка с топ-весом (position пересчитается детерминированно, Р5 — ноль новых механизмов); (3) **наследование веса** (hypercorrection): замещение наследует подтверждённость опровергнутого, не стартует с базового w — иначе юзеру пришлось бы повторять правду K раз; формула → ТЗ (Н8). Голое отрицание (без replacement) — слабая форма (CIE): ослабление confidence + уточнение conditions, противоположный полюс не навязывается (¬A ≠ B), дрейф в центр не принуждается («середина» — сама заявление); для прескриптивов голый kill — Р32. Научные опоры → словарь 06 §8.1 (**Р44**). Правки: 07 §5, 10 §2, 13 §2.1, 09 §4. (сессия; драфт 27)
- **Р42. Опровержение оси: генерализация `retired`-триггера + зрелость цели.** Триггер `retired` расширен с kill-insight («юзер увидел и убил») до прямого опровержения («такой оси во мне нет»): мета-факт ADD-only (Р6) + перевод статуса; владелец — Gestalting детерминированным кодом (Р33), fast path (мимо каденций). Зрелость цели: **emerging** — одно опровержение (идиографизм Р4/Келли: юзер — хозяин конструктов, навязанная неукоренившаяся категория сопротивления не заслуживает); **active** — накопительно **K≥2 независимых опровержений** — симметрия порогов: рождение оси требует 2 независимых фактов, смерть зрелой — 2 опровержений (опоры: ассимиляция Пиаже — зрелая схема сопротивляется, CIE, Деннет — защитное отрицание). Revival открыт (`retired` ≠ удалена). Правка: 09 §4. (сессия; драфт 27)
- **Р43. Немедленность эффекта коррекции: форс-пересборка слепка + priority-флаг очереди.** (1) Явная коррекция юзера → **форс-запуск пересборки** PortraitSnapshot немедленно, не ждём каденции (~10 мин): коррекция пишет факт → system_time → cutoff сместился (Р19) → форс; владелец Reconciliation, single-flight через lease Р10 (форс сливается с идущей пересборкой); коррекция редкая → дёшево. Опора: transactive memory (Wegner 1985) — партнёрская память реагирует на поправку немедленно; trust-луп. Оговорка: мгновенный эффект гарантирован для WORLD-вердиктов и позиций (детерминированная пересборка, Р5); накопительный порог K≥2 active-осей (Р42) может не дать мгновенного эффекта — корректно по построению (защита от защитного отрицания). (2) **Priority-флаг** user-correction-кандидатов в очереди разбора Dreaming (Р39): разбираются первыми в ближайшем цикле (judge-случаи конфликтов замещения, Р25); отдельная подочередь отвергнута (структурно больше, чем требует редкое событие). Правки: 13 §2.1, 14 §5. (сессия; драфт 27)
- **Р44. Словарь коррекции (рассылка по Р22).** 06 §8.1 добавлены: **реконсолидация** (Nader & LeDoux 2000; Sevenster/Kindt; Bisaz et al. 2014 уже опирает гистерезис 17 §7), **hypercorrection effect** (Butterfield & Metcalfe 2001), **continued influence effect** (Lewandowsky et al. 2012), **source monitoring** (Johnson, Hashtroudi & Lindsay 1993), **transactive memory** (Wegner 1985). Позиционирование (06 §6): пара юзер–агент — распределённая (транзактивная) память, взаимные поправки — нормальный режим; канал Correction — не API-надстройка. (сессия; драфт 27)
- **Р45. ADR eval-каркаса и операционализация тезис-чека (драфт 28).** Каркас предиктивной метрики Р36 — каталог **`eval/`** (имя по узнаваемости Р24: «golden» — жаргон тест-культуры, «harness» — свойство не сущность, «benchmark» — коллизия с Р37, «thesis» — протухает; артефакт персистентный: smoke-прогон → релизный гейт, ярусы = конфиги одного кода). Решения: (1) **поглощение кода спайка** — `eval/` копирует требуемое (Encoding→слепок, LLM-клиент, конфиг), спайк нетронут до архивации (Р34); (2) **точка** = срез (T + триггер + истина-продолжение + машинные проверки), 20–50 шт., разметка руками; **W-требование** — L1-точка включается только при наличии в слепке на T факта/конструкта, релевантного истине (разметчик вне системы; C-точки — без покрытия); (3) гигиена: живой лог/прогоны вне VCS, точки коммитятся только абсолютно обезличенными; (4) плечи A/B на одном хосте (внешний OpenAI-совместимый роутер, temperature 0), кэш плеча B раз на версию; (5) **статистика go/no-go**: односторонний точный знаковый тест (McNemar exact) на **решённых парах**, α=0.05 (мощность: 20 решённых → 15 побед A, 30 → 20, 50 → 32 — перевес ~2:1, доказательство существования; слабые эффекты — полный ярус) + байесовский posterior P(A>B) как руль добора; **вердикты асимметричны**: go безусловен, no-go всегда условен — трёхуровневая диагностика недобора (**лог бедный / Encoding не извлёк / инъекция не переводится**; та же разметка даёт диагноз) + метрика конструируемости; «концепт не тянет» — только узкий случай (W-точек достаточно, покрытие подтверждено, lift стабильно нет на повторных прогонах); тезис формулируется **условно** («когда портрет содержит релевантный сигнал — переводится в поведение»); цикл прогонов вместо одиночного выстрела (повторы дёшевы — кэши Р36); (6) структура «данные+код» без преждевременной модуляризации (`dataset/` + runner). Вне рамки тезис-чека: судьи, полный ярус, WORLD-recall, Р37. ADR: `docs/spec/28`. (сессия; драфт 28)
