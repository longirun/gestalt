## 0. Карта документов и структура репозитория

Рабочая зона организована по принципу: **корень** — точка входа и верстак; **`docs/`** — каноническая база знаний; **`docs/archive/`** — отработанные материалы.

| Раздел | Содержание | Назначение |
|---|---|---|
| `STATUS.md` | Этот файл | Главная точка входа: статус, реестр решений (Р1–Р19), открытые нити (Н1–Н11), текущий шаг |
| `drafts/` | Файлы текущих сессий | Рабочий верстак: штурм концепции и временные файлы обсуждений перед фиксацией в канон |
| `docs/concept/` | 06 (фундамент), 07 (матрица наблюдения), 10 (проекты и применимость), 11 (предиктивная метрика), 13 (таксономия процессов), 14 (PortraitSnapshot) — **канон**; 09 (Construct) — в проработке (Н4) | Теоретическое ядро концепции |
| `docs/spec/` | 02, 03 (методология EARS для ТЗ) + будущее ТЗ | Требования и спецификации |
| `docs/research/` | 12 (реестр внешних материалов: аналоги NGT/Honcho/HippoGraph/Cognee + собственный стенд + рамки), 05.2 (дизайн-заметки) | База знаний, анализ аналогов, опыт и антипаттерны |
| `docs/archive/` | 04 (карточка алгоритма) | Плоский архив устаревших и отработанных материалов |

Порядок чтения для погружения в проект: 
**`STATUS.md` → `docs/concept/` (06 → 07 → 09 → 10 → 11 → 13 → 14) → `docs/research/` (12 — реестр аналогов; 05.2) → `docs/archive/` (по необходимости)**.

### Процесс «drafts → canon» (конвенция от 2026-09-03)

1. **Сессия обсуждения** → один файл `drafts/NN - Тема -черновик.md`; сквозная нумерация, номера не переиспользуются.
2. **Источник истины — STATUS.md**: решения (РNN) и нити (НNN) регистрируются здесь сразу по ходу сессии; остальные доки лишь ссылаются на РNN. Спорное с любым документом разрешается реестром.
3. **Кристаллизация**: когда решение «перестало дышать», файл переносится в `docs/{concept|spec|research}/` **с сохранением номера** (drafts/10 → docs/concept/10), шапка меняется на каноническую, нерешённые остатки переезжают в открытые нити; draft удаляется.
4. **Исторические доки** (весь 05.х и `docs/archive/`): читаются как источник идей, а не как истина; живое из них уже поглощено реестром решений.
5. **Гигиена реестра.** Строка Р — текущая истина + указатель, не летопись. При 3+ поправках к одному решению — кристаллизация: содержание → concept/research-док, строка переписывается набело, номер стабилен. Нити закрываются с критерием (решение / кристаллизация / отказ), не живут вечно. (конвенция от 2026-09-04)

## 1. Реестр принятых решений

Обозначения: Р<N> — решение; в скобках — первоисточник.

- **Р1. Переработка, не аналог.** Gestalt — не порт Honcho, а устранение концептуальных дефектов; обратная совместимость только по данным (мигратор + golden-master валидация). (01, удалён → сессия) *(Поправка Р15: Honcho понижен до обычного аналога — data-compat/мигратор как обязательство сняты.)*
- **Р2. Рамка когнитивного архитектора.** Три вопроса: **что** помнить (эпизодическое/семантическое/социальное — Тульвинг), **как** помнить (кодирование/консолидация/схемы — Пиаже), **кого** помнить и как узнать человека (идиографическое vs номотетическое). (06)
- **Р3. Наблюдение и атрибуция.** Пара (observer, observed) реформирована в колонку `observer` + перспективу как query-параметр; имя — `observer` (ToM-канон, миграция Honcho 1:1). Симметричный `Actor {id, kind: PERSON|AGENT}`; матрица наблюдения AU/AA/UA/UU; **v1 = AU** (агент наблюдает человека), двери к остальным квадрантам открыты. Смена версии агента = смена эпохи (событие), не supersession. (07, 05.2)
- **Р4. Идиографическое ядро + номотетические проекции.** Ядро — конструкты Келли (открытое, community); проекции (Big Five и т.п.) — enterprise-слой (v2+, монетизация). Граница монетизации совпадает с теоретической границей. (06)
- **Р5. Construct = Axis + Instance.** `ConstructAxis` (биполярная ось, переиспользуемая, иерархическая) отдельно от `ConstructInstance` (положение конкретного observed: position + conditions + confidence + evidence lineage≥2 + valid_time). Конструкт всегда привязан к человеку; WORLD-факты — не конструкты. LLM — только именование оси; position вычисляется детерминированно из evidence. (09)
- **Р6. Гибридная дисциплина приёма.** Fast path: батч-экстракция (один LLM-вызов на батч, накопление по токенам + age-flush) + детерминированный дедуп (точный + семантический по косинусу; усиление счётчиком вместо дублирования) — **без LLM-суждений**. Slow path («сон»): supersession, противоречия, индукция — только здесь, с lineage. Поправка к карточке 04. (`docs/research/12` §12.2) *(Уточнение из §12.3, негативный результат HippoGraph: supersession меняет **статус** факта — историчность, — но не подавляет retrieval; старые факты остаются reasoning-контекстом, штраф на их видимость вредит.)*
- **Р7. Pure PostgreSQL для v1.** PG 16+ / pgvector; графовые workload'ы (lineage, иерархии, supersession — на 90% мелкохоповые) — таблицы рёбер + recursive CTE + JSONB/GIN. Порт `GraphStore` SPI: CTE-реализация по умолчанию / Apache AGE опция / Neo4j enterprise-escape. AGE не блокер и не требование ядра. (сессия; независимо подтверждено `docs/research/12` §12.2)
- **Р8. Pass-once + batch-amortized** — архитектурный инвариант (NFR): сообщение не перечитывается LLM многократно; вся тяжёлая работа — от хранимых фактов, не от сырых диалогов. LLM только на семантических границах: экстракция, именование осей, запрос-синтез, judge. (сессия)
- **Р9. Дескриптивы ≠ прескриптивы.** Факты/выводы (WORLD/PSYCHE) и рекомендации/советы — раздельные хранилища; исключение самореференсного дрейфа системы («система советует о себе»). (05.2)
- **Р10. Архитектурные паттерны распределённой памяти.** Зафиксировать в дизайне: reconciler self-healing (lease + backoff + poison-изоляция), reinforcement-счётчик подтверждений вместо дублирования, токен-батчинг с age-flush, session-purity явных фактов, fail-closed на пустых IN-фильтрах, иерархический конфиг со снапшотом состояния, write-time fan-out наблюдателей (LLM не множится), surprisal-подсказки без LLM. Рассмотреть: компактные слепки портрета, лестницу бюджетов рассуждений. Исключить антипаттерны: недетерминированные лимиты итераций, зависимость от физического порядка строк, утечку векторов. (`docs/research/12` §12.2)
- **Р11. Workspace исключён из v1.** Иерархия `User → Project → Session → Message`; изоляция — RLS по `user_id`; tenant = деплой. Внешние идентификаторы тенантов при импорте сворачиваются в метку провенанса. Возврат сущности — по триггерам (hosted SaaS / командные проекты UU / AA / billing), ввод аддитивной миграцией; API v1 не закладывает workspace в пути. (`docs/concept/10` §6)
- **Р12. Метрика и прескриптивы в v1 (вариант А развилки Н2).** Состав v1: ядро + Construct-minimal + метрика + прескриптивы. Метрика: офлайн golden-набор (L1 выбор + L2 ответ; парный A/B на срезе времени, lift «с портретом vs без», LLM-судьи; регресс в CI) — обязательна; онлайн-контур L3 = acceptance-rate прескриптивов. Прескриптивы — минимальная форма «канал фидбека» (kill-insight + acceptance), без отдельного UI и советчика; отдельное хранилище по Р9. Отложено: Big-Five-проекции, полный Пиаже-цикл, repertory-grid, AA-квадрант. Рамка метрики: `docs/concept/11`. (сессия; Н2)
- **Р13. Разводка измерений факта: owner / domain / scope.** `owner` — чей факт (всегда юзер, из сессии); `domain ∈ {WORLD, PSYCHE}` — **о чём** факт (онтологическая категория: инвариант чистоты портрета, дефолты scope, метрика — 11 §2); `scope ∈ {SESSION, PROJECT, USER}` — **докуда** факт релевантен (радиус видимости). Устранена омонимия: прежде «scope» означал оба измерения (05.2, 07 — переименовано в `domain`; 05.1 к моменту правки уже удалён); слово «scope» — только радиус. В PG-схеме колонка `fact_domain` (`DOMAIN` — keyword в PG). (сессия; ревью терминологии) *(Валидация стендом, §12.6: routing/tier — свойство факта в сервисе, не тег в контракте агента — теги `#global`/`#user` пережили две смены бэкендов и умерли, оставив контракт-дрейф docs↔код.)*
- **Р14. Методика метрики — адаптация подходов NGT** (`docs/research/12` §12.1). Три элемента в рамку метрики (11 §3–4): (а) контрольная ось **no-false-memory** — вопросы не по теме, замер leak-rate на уровне ответа LLM: память обязана молчать, когда не нужна (инъекция нерелевантного = ложная память); (б) **filler-инвариант golden-диалогов** — полезные факты выталкиваются за окно истории нейтральными ходами, чтобы плечо-контроль физически не имело доступа и lift был чистым; (в) **формат golden-датасета** — типизированный jsonl-сценарий (факты + filler + вопрос + expect_keywords + категория); сырые прогоны и провалы коммитуются. (анализ аналогов) *(Дополнение из §12.5: **BEAM** (arXiv 2510.27246) — внешний бенчмарк разговорной памяти, 10 способностей ≈ наши мишени (abstention = ось C, knowledge updates = supersession, temporal = valid_time) — внешний арбитр против self-benchmark; плюс фильтр состава golden-набора: обязательны temporal- и multi-hop-точки, где спотыкаются KG-системы.)*
- **Р15. Позиционирование относительно внешних платформ.** Gestalt — самостоятельная когнитивная архитектура; статус прямого предшественника или обязательств обратной совместимости с какими-либо внешними системами снят (поправка к Р1). Перенос данных при необходимости реализуется через стандартные внешние адаптеры (чтение открытых форматов экспорта в модель Gestalt). База знаний по рынку ведётся в реестре аналогов `docs/research/12`. (сессия)
- **Р16. Консолидация исследовательской базы.** Первичные рабочие черновики и разрозненные заметки консолидированы в системном реестре аналогов `docs/research/12`. Репозиторий очищен от устаревших промежуточных материалов. Ссылки в живых документах переведены на разделы реестра 12. (сессия)
- **Р17. Лицензия и платформа ядра.** Лицензия проекта — **Apache 2.0** (максимальная открытость для community и enterprise-интеграций, связка с Р4). Платформа: **Java 21 LTS**, zero-dependency / zero-framework core (чистые Java SPI контракты, виртуальные потоки Loom, стандартные механизмы concurrency и observability). Фреймворк-адаптеры (Spring Boot Starter, Micronaut) выносятся в отдельные внешние модули; доменное ядро от них изолировано. (сессия; перенос инвариантов из 01, удалён)
- **Р18. Таксономия процессов памяти.** Write-path — триада псих-процессов: **Encoding** (сек, fast path) → **Dreaming** (часы, slow path «сон») → **Gestalting** (дни, индукция схем/портрет) + фоновая **Reconciliation** (Р10). Имена — герундии с теоретической опорой; инженерные синонимы — словарь пар; Honcho-наследие снято (термины Honcho — только в реестре 12); read-path — `ContextProducer`-стратегии вне ядра (Н5; snapshot — **Р19**). Канон: `docs/concept/13 - Таксономия процессов памяти.md`. (сессия; Н1)
- **Р19. PortraitSnapshot.** Материализованная проекция портрета — не источник истины (инвариант 09 §3), пересбор детерминированный, **0 LLM**. Состав — секции с приоритетами: **CRITICAL** (критичные факты, highest) → **CONSTRUCTS** (активные Instance) → **PREFERENCES** (стабильные); ≤40×200, `(unconfirmed)` при conf < 0.8. Инвалидация — водяной знак `max(system_time входов) > watermark` (события на write-path ничего не пишут; dirty-flag отвергнут). Перестройка — периодическая джоба (дефолт 10 мин, конфигурируемо) в контуре **Reconciliation** (lease+backoff+poison, Р10): юзер всегда на готовом профиле; coalescing/prewarm — следствия, не механизмы. Read-path v1 = слепок + WORLD-recall, без LLM (Р8); бюджетная лестница и LLM-стратегии `ContextProducer` → Н5. Канон: `docs/concept/14 - PortraitSnapshot.md`. (сессия; П2; Н3)

## 2. Итоги архитектурной оценки

### 2.1 Подтверждённые архитектурные инварианты
Гибридный приём (Р6), хранилище Pure PostgreSQL + pgvector (Р7), симметрия Actor (Р3), расщепление Construct (Р5), разделение дескриптив/прескриптив (Р9), самовосстанавливающийся Reconciler (Р10).

### 2.2 Предложения в проработке (статус: [ПРЕДЛОЖЕНО] — требуют явного решения)

- **П1. Дисциплина жизненного цикла осей** *(было: Seed Axes + дисциплина)*. **Seed-словарь — ✅ отвергнут для v1** (2026-09-04): у словаря нет потребителя в v1 — axis sprawl решается merge-дисциплиной, жизненный цикл — статусами; рантайм-prior ломал бы идиографичность ядра (Р4, самосбывающийся prior); фикстуры golden-набора — локальные ожидания датасета (Р14), не системный канон. Словарь канонических осей — v2+ (community-реестр, 09 §2). Остаток П1 в обсуждении (Н4): семантика «независимых сессий» и порог K для `emerging → active`; детерминированный порог слияния осей по косинусной близости до подключения LLM-судьи. Мотив: axis sprawl («краткость vs детализация» ≈ «лаконичность vs многословие» — LLM плодит синонимичные оси).
- П2 (PortraitSnapshot-lite) — ✅ принято (2026-09-04) → **Р19**, канон `docs/concept/14 - PortraitSnapshot.md`.

### 2.3 Снятые расхождения

MVP-состав из прежнего §4 аудита молча исключил прескриптивы, предиктивную метрику, observability-otel и server. Это **не решение** — переведено в открытую нить Н5. `gestalt-reconciler` как отдельный модуль — вариант упаковки, тоже Н5.

## 3. Открытые вопросы (в порядке приоритета)

- **Н1. Функциональная таксономия и имена воркеров.** ✅ Решено (2026-09-04): конвейер write-path — триада процессов **Encoding → Dreaming → Gestalting** (каденции сек/часы/дни) + фоновая **Reconciliation** → **Р18**. Имена — псих-термины с теоретической опорой (герундии-процессы, не персонажи); инженерные синонимы extraction/consolidation/induction — словарь пар. Read-path выведен из таксономии: не процессы ядра, а API-слой `ContextProducer` со стратегиями (snapshot-быстро / LLM-микс / точный агентный); хвост «слой сборки контекста» (отбор/ранжирование/бюджет/префетч) → **Н5** (+Н3). Н6 переформулирована: emerging-оси — Dreaming или Gestalting.
- **Н2. Метрика и прескриптивы в v1.** ✅ Решено (2026-09-03): вариант **А** — метрика + прескриптивы в v1 → **Р12**. Рамка метрики — `docs/concept/11` (мишень = наблюдаемое поведение юзера; парный A/B на срезе времени; сорта точек L1/L2/L3; изоляция вклада портрета от WORLD-recall). История (черновые решения 7–8): метрика = 2 контура — офлайн golden-набор (20–50 диалогов, predictive lift, LLM-judge; датасет пилотного стенда, §12.6) + онлайн acceptance-rate прескриптивов; v1-минимализм = ядро + Construct-minimal + метрика + прескриптивы; отложить Big-Five-проекции, полный Пиаже-цикл, repertory-grid, AA-квадрант.
- **Н3. PortraitSnapshot-lite (П2).** ✅ Решено (2026-09-04): слепок = материализованная проекция, секции CRITICAL/CONSTRUCTS/PREFERENCES, watermark-инвалидация, джоба Reconciliation (10 мин) → **Р19**, канон `docs/concept/14 - PortraitSnapshot.md`. Read-path v1 = слепок + WORLD-recall без LLM; LLM-стратегии → Н5.
- **Н4. Минимальная схема Construct (остаток П1).** Стартовый словарь — ✅ отвергнут (2026-09-04, П1): словарь осей = v2+ (community-реестр, 09 §2). Открыто: семантика «независимых сессий» и порог K; порог слияния осей. Связка с 09 §6: входят ли conditions и иерархия осей в v1. Плюс хвост из §12.3: condition `permanence=user-asserted` — явное «запомни навсегда» от юзера исключает факт из TTL-смерти (ядро идеи anchor-policies HippoGraph, выраженное условием на факте, без реестра политик).
- **Н5. Архитектурная декомпозиция и модульный состав.** Прорабатывается строго **после** окончательного утверждения концептуального ядра (Н4, Н6, Н11). Ранние наброски архитектуры (05.1, удалён) аннулированы: они забегали вперёд паровоза и искусственно лимитировали концепт. Архитектура будет выведена из утверждённых доменных требований: упаковка ядра (zero-framework core по Р17), изоляция хранилищ (Pure PG по Р7), состав модулей (reconciler, server, starters) и мосты ингеста внешних источников (§12.4, П3; двухконтурная интеграция §12.5). Плюс read-path API из Н1 (Р18): `ContextProducer`-стратегии (snapshot Р19 / LLM-микс / точный агентный; dual-path префетч §12.2, per-prompt-инжект + тег `_source` §12.5, hints-аккумулятор + topics-fingerprint §12.6).
- **Н6. Кто пишет emerging-кандидаты осей** — Dreaming (часы, консолидация) или Gestalting (дни, индукция схем); критерии смены статусов оси.
