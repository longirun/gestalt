### Процесс «drafts → canon» (конвенция от 2026-09-03)

1. **Сессия обсуждения** → один файл `drafts/NN - Тема -черновик.md`; сквозная нумерация, номера не переиспользуются.
2. **Источник истины — STATUS.md**: решения (РNN) и нити (НNN) регистрируются здесь сразу по ходу сессии; остальные доки лишь ссылаются на РNN. Спорное с любым документом разрешается реестром.
3. **Кристаллизация**: когда решение «перестало дышать», файл переносится в `docs/{concept|spec|research}/` **с сохранением номера** (drafts/10 → docs/concept/10), шапка меняется на каноническую, нерешённые остатки переезжают в открытые нити; draft удаляется.
4. **Исторические доки** (весь 05.х и `docs/archive/`): читаются как источник идей, а не как истина; живое из них уже поглощено реестром решений.
5. **Гигиена реестра.** Строка Р — текущая истина + указатель, не летопись. При 3+ поправках к одному решению — кристаллизация: содержание → concept/research-док, строка переписывается набело, номер стабилен. Нити закрываются с критерием (решение / кристаллизация / отказ), не живут вечно. (конвенция от 2026-09-04)
6. **История — в CHANGELOG.** Записи «Обновление (...)» — только в `CHANGELOG.md`; STATUS — снапшот текущего состояния. (конвенция от 2026-09-04, Р21)
7. **Терминология — через фундамент.** Словарь вводится/меняется только в 06 §8 (дисциплинарный источник или заявленный бренд); остальной корпус ссылается, не изобретает. (конвенция от 2026-09-04, Р22)

## 1. Реестр принятых решений

Обозначения: Р<N> — решение; в скобках — первоисточник.

- **Р1. Переработка, не аналог.** Gestalt — вдохновлен идеей Honcho, но не порт, а устранение концептуальных дефектов.
- **Р2. Рамка когнитивного архитектора.** Три вопроса: **что** помнить (эпизодическое/семантическое/социальное — Тульвинг), **как** помнить (кодирование/консолидация/схемы — Пиаже), **кого** помнить и как узнать человека (идиографическое vs номотетическое). (06)
- **Р3. Наблюдение и атрибуция.** Пара (observer, observed) реформирована в колонку `observer` + перспективу как query-параметр; имя — `observer` (ToM-канон, миграция Honcho 1:1). Симметричный `Actor {id, kind: PERSON|AGENT}`; матрица наблюдения AU/AA/UA/UU; **v1 = AU** (агент наблюдает человека), двери к остальным квадрантам открыты. Смена версии агента = смена эпохи (событие), не supersession. (07, 05.2)
- **Р4. Идиографическое ядро + номотетические проекции.** Ядро — конструкты Келли (открытое, community); проекции (Big Five и т.п.) — enterprise-слой (v2+, монетизация). Граница монетизации совпадает с теоретической границей. (06)
- **Р5. Construct = Axis + Instance.** `ConstructAxis` (биполярная ось, переиспользуемая, иерархическая) отдельно от `ConstructInstance` (положение конкретного observed: position + conditions + confidence + evidence lineage≥2 + valid_time). Конструкт всегда привязан к человеку; WORLD-факты — не конструкты. LLM — только именование оси; position вычисляется детерминированно из evidence. (09)
- **Р6. Гибридная дисциплина приёма.** Fast path: батч-экстракция (один LLM-вызов на батч, накопление по токенам + age-flush) + детерминированный дедуп (точный + семантический по косинусу; усиление счётчиком вместо дублирования) — без LLM-суждений. Slow path («сон»): supersession, противоречия, индукция — только здесь, с lineage. Supersession меняет **статус** факта (историчность), но не подавляет retrieval: старые факты остаются reasoning-контекстом, штраф на их видимость вредит (негативный результат HippoGraph). Канон: 16 §4; реестр 12 §12.2/§12.3.
- **Р7. Pure PostgreSQL для v1.** PG 16+ / pgvector; графовые workload'ы (lineage, иерархии, supersession — на 90% мелкохоповые) — таблицы рёбер + recursive CTE + JSONB/GIN. В v1 мы **отказываемся от абстракции GraphStore SPI** (не строим слой совместимости с графовыми БД), так как концепция отлично ложится на реляционную структуру. Рассмотрение выделенного графового движка (Apache AGE, Neo4j) переносится на майлстоун **v2+** (см. Н15). (сессия; независимо подтверждено `docs/research/12` §12.2)
- **Р8. Pass-once + batch-amortized** — архитектурный инвариант (NFR): сообщение не перечитывается LLM многократно; вся тяжёлая работа — от хранимых фактов, не от сырых диалогов. LLM только на семантических границах: экстракция, именование осей, judge (read-path v1 — 0 LLM **в движке**, формулировка запроса — потребитель, **Р35**; запрос-синтез — стратегия `ContextProducer` v2+, Н5). (сессия)
- **Р9. Дескриптивы ≠ прескриптивы.** Факты/выводы (WORLD/PSYCHE) и рекомендации/советы — раздельные хранилища; исключение самореференсного дрейфа системы («система советует о себе»). (05.2)
- **Р10. Архитектурные паттерны распределённой памяти.** Зафиксировать в дизайне: reconciler self-healing (lease + backoff + poison-изоляция), reinforcement-счётчик подтверждений вместо дублирования, токен-батчинг с age-flush, session-purity явных фактов, fail-closed на пустых IN-фильтрах, иерархический конфиг со снапшотом состояния, write-time fan-out наблюдателей (LLM не множится), surprisal-подсказки без LLM. Рассмотреть: компактные слепки портрета, лестницу бюджетов рассуждений. Исключить антипаттерны: недетерминированные лимиты итераций, зависимость от физического порядка строк, утечку векторов. (`docs/research/12` §12.2)
- **Р11. Workspace исключён из v1.** Иерархия `User → Project → Session → Message`; изоляция — RLS по `user_id`; tenant = деплой. Внешние идентификаторы тенантов при импорте сворачиваются в метку провенанса. Возврат сущности — по триггерам (hosted SaaS / командные проекты UU / AA / billing), ввод аддитивной миграцией; API v1 не закладывает workspace в пути. (`docs/concept/10` §6)
- **Р12. Метрика и прескриптивы в v1 (вариант А развилки Н2).** Состав v1: ядро + Construct-minimal + метрика + прескриптивы. Метрика: офлайн golden-набор (L1 выбор + L2 ответ; парный A/B на срезе времени, lift «с портретом vs без», LLM-судьи; регресс в CI) — обязательна; онлайн-контур L3 = acceptance-rate прескриптивов. Прескриптивы — минимальная форма «канал фидбека» (kill-insight + acceptance), без отдельного UI и советчика; отдельное хранилище по Р9. Отложено: Big-Five-проекции, полный Пиаже-цикл, repertory-grid, AA-квадрант. Рамка метрики: `docs/concept/11`. (сессия; Н2)
- **Р13. Разводка измерений факта: owner / domain / scope.** `owner` — чей факт (всегда юзер, из сессии); `domain ∈ {WORLD, PSYCHE}` — **о чём** факт: **вид знания, не объект** (инференс о личности = PSYCHE; наблюдаемое о мире, включая юзера как объект, = WORLD; канон границы — 10 §3.1 = 06 §8.3); онтологическая категория задаёт инвариант чистоты портрета, дефолты scope, метрику (11 §2); `scope ∈ {SESSION, PROJECT, USER}` — **докуда** факт релевантен (радиус видимости). Омонимия устранена: слово «scope» — только радиус. Routing/tier — свойство факта в сервисе, не тег в контракте агента (полевая валидация стендом, 12 §12.6). В PG-схеме колонка `fact_domain` (`DOMAIN` — keyword в PG).
- **Р14. Методика метрики — адаптация подходов NGT** (12 §12.1). Три элемента в рамку метрики (11 §3–4): (а) контрольная ось **no-false-memory** — вопросы не по теме, замер leak-rate на уровне ответа LLM: память обязана молчать, когда не нужна (инъекция нерелевантного = ложная память); (б) **filler-инвариант golden-диалогов** — полезные факты выталкиваются за окно истории нейтральными ходами, чтобы плечо-контроль физически не имело доступа и lift был чистым; (в) **формат golden-датасета** — типизированный jsonl-сценарий (факты + filler + вопрос + expect_keywords + категория); сырые прогоны и провалы коммитуются; в составе обязательны temporal- и multi-hop-точки, где спотыкаются KG-системы. Внешний арбитр — **BEAM** (10 способностей ≈ наши мишени: abstention = ось C, knowledge updates = supersession, temporal = valid_time) и SOTA-ориентир Mem0 — трек сравнимости → **Р37**.
- **Р15. Позиционирование относительно внешних платформ.** Gestalt — самостоятельная когнитивная архитектура. Перенос данных из других систем при необходимости следует реализовать через стандартные внешние адаптеры (чтение открытых форматов экспорта в модель Gestalt, требуется проработка). База знаний по рынку ведётся в реестре аналогов `docs/research/12`. (сессия) *(Дополнение из §12.7: пересечение с recall-слоями типа Mem0 — только commodity-дисциплины extraction/retrieval; ядро — идиографическая модель человека (Construct, Р4/Р5) с предиктивной метрикой (Р14) — не дублируется: их цель «что было сказано», наша — «какой человек и что он выберет».)*
- **Р16. Консолидация исследовательской базы.** Первичные рабочие черновики и разрозненные заметки консолидированы в системном реестре аналогов `docs/research/12`. Репозиторий очищен от устаревших промежуточных материалов. Ссылки в живых документах переведены на разделы реестра 12. (сессия)
- **Р17. Лицензия и платформа ядра.** Лицензия проекта — **Apache 2.0** (максимальная открытость для community и enterprise-интеграций, связка с Р4). Платформа: **Java 21 LTS**, zero-dependency / zero-framework core (чистые Java SPI контракты, виртуальные потоки Loom, стандартные механизмы concurrency и observability). Фреймворк-адаптеры (Spring Boot Starter, Micronaut) выносятся в отдельные внешние модули; доменное ядро от них изолировано. (сессия; перенос инвариантов из 01, удалён)
- **Р18. Таксономия процессов памяти.** Write-path — триада псих-процессов: **Encoding** (сек, fast path) → **Dreaming** (часы, slow path «сон») → **Gestalting** (дни, индукция схем/портрет) + фоновая **Reconciliation** (Р10). Имена — герундии с теоретической опорой; инженерные синонимы — словарь пар; Honcho-наследие снято (термины Honcho — только в реестре 12); read-path — `ContextProducer`-стратегии вне ядра (Н5; snapshot — **Р19**). Канон: `docs/concept/13 - Таксономия процессов памяти.md`. (сессия; Н1)
- **Р19. PortraitSnapshot.** Детерминированная сборка когнитивных схем Бартлетта для обеспечения O(1) latency (Р8, Бартлетт 1932, van Kesteren 2012 / SLIMM; 0 LLM). Материализованная проекция портрета — не источник истины (инвариант 09 §3), пересбор детерминированный, **0 LLM**. Состав — секции с приоритетами: **CRITICAL** (критичные факты юзера — санкционированное WORLD-вкрапление, 14 §2; highest) → **CONSTRUCTS** (поведенческие принципы — write-time директивы, 14 §6; lifecycle директивы — там же) → **PREFERENCES** (стабильные); ≤40×200, `(unconfirmed)` при conf < 0.8. Инвалидация — точка отсечки `max(system_time входов) > cutoff` (события на write-path ничего не пишут; dirty-flag отвергнут). Перестройка — периодическая джоба (дефолт 10 мин, конфигурируемо) в контуре **Reconciliation** (lease+backoff+poison, Р10): юзер всегда на готовом профиле; coalescing/prewarm — следствия, не механизмы. Read-path v1 = слепок + WORLD-recall, без LLM в движке (Р8; контракт запроса — **Р35**); бюджетная лестница и LLM-стратегии `ContextProducer` → Н5. Канон: `docs/concept/14 - PortraitSnapshot.md`. (сессия; П2; Н3)
- **Р20. Роадмап релизов.** Планы релизов описаны явно в `ROADMAP.md` (корень): v1 — состав по Р12 (ядро + Construct-minimal + метрика + прескриптивы, квадрант AU); v2 — триггерные сущности (workspace/мультиаренда, AA-квадрант, Big-Five-проекции, community-словарь осей, prospective memory, дрейф-метрика); v3 — белое пятно (состав реестром не определён; резерв под сработавшие триггеры v2, маркеры — 10 §6). Роадмап — проекция реестра решений: новые обязательства только через РNN. (сессия)
- **Р21. Разделение статуса и истории.** STATUS.md — снапшот текущего состояния (реестр, нити, следующий шаг); хронология «Обновление (...)» вынесена в `CHANGELOG.md` (новые записи сверху). Продолжение принципа гигиены (§0 п.5): STATUS — не летопись. (сессия)
- **Р22. Терминология канона.** Словарь проекта вводится разделом «Терминология» в фундаменте (06 §8): заимствованные термины — с дисциплинарным источником (психология / нейронаука / инжиниринг) и «берём / отвергаем»; имена-бренды (Dreaming, Gestalting, PSYCHE/WORLD, прескриптив, L1/L2/L3, emerging/active, AU/AA/UA/UU) — заявлены явно с дисциплинарным прототипом. Конвенция: термин канона обязан иметь источник или статус бренда; новые термины — только через 06 §8, корпус ссылается, не чеканит приватный новояз. Критерий: узнаваемость специалистом психологии или инженерии. (сессия; снимает риск самодеятельной терминологии)
- **Р23. Identity факта WORLD и условия применимости.** Для STATE (полный anchor) identity = `(owner, scope, project_id, subject_norm, predicate_norm, conditions)`; `object` — версииемое значение, в identity не входит («Java 21» vs «Java 21 LTS» — одна пропозиция). Инвариант **≤1 ACTIVE на identity** (реляционная FD; частичный unique-индекс ловит гонки батчей). Fast path — двухшаговый детерминированный дедуп (16 §4.1): identity-lookup → сравнение нормализованного object (равен → reinforcement, отличается → кандидат supersession, нет → новый факт); NARRATIVE/EVENT — семантическая ветка. `conditions` — first-class поле, входит в identity: разные conditions → **sibling** — сосуществующие истины («5432 [dev], 5433 [prod]»), не supersession (прототип MV-register/CRDT). Custom-предикаты — та же механика; словарь предикатов — эмерджентный (пустой при рождении — доменная нейтральность), конвергенция — write-time feedback, нормализация object — домен-нейтральные канонизаторы форм. Консолидация словарей — единый механизм на четыре пространства имён (оси, предикаты, subject-имена, conditions-теги) → **Р25** (16 §2.3). Источники (Р22): Кинч и ван Дейк 1978, Кодд/FD, ACT-R base-level activation, Шапиро 2011 (MV-register).
- **Р24. «Вид» (kind) вместо «сорт».** Классификатор природы факта переименован: поле `sort` → `kind`, «сорт факта» → «вид факта» (STATE/NARRATIVE/EVENT, 16 §2.2); заодно «сорта точек» → «виды точек» (L1/L2/L3, 11 §4). Мотив: «сорт» в русском читается как грейд/сортировка — провал критерия узнаваемости (Р22). Источник: родовидовое деление (Аристотель); `kind` — идиоматика enum'ов в API; семантически точный прототип sortal (класс, задающий условия тождественности) — примечанием в словаре 06 §8.2. Конвенция 06 §8.4 соблюдена: рассылка по корпусу (06, 11, 16, STATUS, drafts). (сессия)
- **Р25. Конвергенция словарей: feedback-промпт и регламент консолидации.** Словарь **кладётся** в extraction-промпт — три пространства WORLD-identity (предикаты, subject-имена, conditions-теги; Р23): мягкое предпочтение существующих («повторяй, если предметно подходит; новое — только для нового свойства») + naming-политика формы (детерминированный regex-валидатор); отбор **top-N по использованию + «ясли»** (гарантированные слоты неподтверждённых новых имён — лечение rich-get-richer); «живое» имя = ≥1 ACTIVE-факт; словарь — проекция над `facts`, не хранимая сущность. **Сигнальный каскад кандидата склейки** (кандидат = любой сигнал ≥ порога): pg_trgm (литеральный) → fingerprint ко-использования (общий subject_norm + близкий object — сильнейший, чистый SQL) → косинус pgvector (дефолт 0.85, привязка к embedding-модели; верифицирован обезличенным аудитом живой базы). **Judge-батч** — контур **Reconciliation** (техгигиена, не Dreaming): лимиты время/объём, drain-режим, вход = пара + мини-конкорданс, каноническое имя по тай-брейку (использование → возраст → лексикография), merge-миграция коллизии ACTIVE — обычный дедуп 16 §4.1; идемпотентность и провенанс — единственная новая таблица `dictionary_pairs` с UNIQUE(namespace, a, b); poison-карантин (Р10). **Канонизаторы `object` v1**: количество (число+единица) / версия (кортеж, хвостовые нули, квалификатор-класс) / путь / url / строка; каскад по форме (url → путь → версия → количество → строка); число↔версия сравнимы по числовому ядру; **принцип консервативности** — канонизатор сливает только заведомо равное, сомнительная близость → судье. Числа — дефолты конфига → ТЗ (Н8). Канон: 16 §2.2 п.4–5, §2.3.
- **Р26. Позиционирование v1 — B2D, без HR-словаря.** Gestalt v1 — инфраструктурный middleware долгосрочной памяти для AI-агентов разработчика (B2D); «психопортрет» в v1 — модель профессионального почерка и архитектурных предпочтений инженера (Деннет-принцип, 06 §6; 16 §1), не психодиагностика и не bossware. Из 06 §5 убран HR-словарь («HR-аналитика, сравнение, дашборды» — bossware-прочтение скептиком); номотетические проекции остаются enterprise-слоем **v2+** (Р4, Р20 — состав реестром). Квадрант AU (Р3), Big Five вне v1 (Р12). Источник: аудит «взгляд скептика» (drafts/15 — закрыт и удалён; гэпы распределены: axis-merge → Р25; tool_result-фильтр, thin-shim API → Н5; lifecycle осей → Н4/Н6). (сессия)
- **Р27. Единая теория динамики памяти: опытное время, несгораемый минимум, единая кривая.** Затухание меряется в **опытном времени** (Δопыт = объём нового опыта интерференционного пула с `last_seen`), календарь исключён — чистая интерференция (Underwood); устаревший мир — проблема истинности → supersession; возраст — метаданные, взвешивает читатель. Единица v1 — **сессия** (грубость осознанная: ошибка только в ранжировании, минимум защищает, использование сбрасывает `last_seen`); точная единица — приоритетный вопрос v2 (чистый SQL, 0 LLM). Формула забывания = потеря **ассоциативной** доступности при сохранении **адресной** (Tulving & Pearlstone 1966; Нуркова/Гофман 2016); единая кривая: w = w_floor + (1−w_floor)·e^{−λ·Δопыт}, λ = ln2/H; **несгораемый минимум** w_floor > 0; H/w_floor по доменам (PSYCHE — длинный H, высокое дно; WORLD — короче) — дефолты → ТЗ (Н8). Применение — только ranking bias + селекция PortraitSnapshot; иммунитет: `permanence=USER_ASSERTED` / `is_critical` → w≡1. PSYCHE v1: статусы `emerging/active/drifted` (`retired` — v2), confidence по Лапласу/Knowledge Vault, гистерезис **K = 2** (дефолт v1), триаж 10 §2; непрерывная интерференция полюсов — v2. Канон: `docs/concept/17` §2/§3/§5/§7.
- **Р28. Интерференционные пулы = scope; события подкрепления.** Радиус релевантности = радиус интерференции: PROJECT-факт ржавеет от опыта своего проекта, USER — от всего опыта юзера, SESSION-эфемер вне динамики (умирает с контейнером). Симметрия read/write: context(S) читает 3 уровня, сессия тикает 2 пула (проектный + юзерский; безпроектная — только юзерский). `last_seen` двигают: дедуп-подтверждение (16 §4.1), Dreaming-реактивация при лифте `SESSION→PROJECT→USER` и кросс-проектной индукции, ко-подтверждение из независимого проекта (10 §4), **использование = доставка факта в контекст сессии** (селекция в слепок / recall с доставкой в Top-K); голый retrieval-hit без доставки — не двигает (Р10: подтверждение ≠ использование; частично закрывает Н10(б)). «Ржавеет только то, что системе никогда не было нужно». Канон: `docs/concept/17` §4. (сессия; ядро Н4)
- **Р29. Доступность истории WORLD (П3 Н12).** Исторические статусы (SUPERSEDED/RETIRED) вне семантического горячего набора, доступны тремя адресными путями: (1) exact по anchor — GIN(anchor) **полный** (единственное расширение индексов; HNSW/FTS — partial ACTIVE-only, инвариант 16 §3.1 цел); (2) навигация от ACTIVE по `superseded_by_id` вниз + от сводного к атомам по `generalized_from: [UUID]` (новое поле схемы 16 §2.1; симметрия `superseded_by_id`); (3) temporal query-side (Н5, soft-dependency). Доступ — в границах scope-видимости (матрица 10 §3.3; Р11). Канон: 16 §2.1/§3.1/§4.2/§4.3 + `docs/concept/17` §6. (сессия; Н12 П3)
- **Р30. Вычислимая важность (П4 Н12).** Важность — вычислимая функция read-path, не атрибут факта; хранимое на следе — только политики доставки и жизни (`is_critical`, `permanence`). Антипаттерн — stored-priority (NGT, 12 §12.1). Канон: 16 §5 (строка-принцип), `docs/concept/17` §3.4. (сессия; Н12 П4)
- **Р31. Независимость свидетельств, merge осей, состав v1 конструкта (закрытие Н4/П1).** (1) **Независимость ко-подтверждения = другой `session_id`**: `count(DISTINCT session_id)` по lineage свидетельств (семантика и границы — канон 17 §7). (2) **Merge осей** — инстанциация каскада Р23/Р25 под неймспейс «оси» (per-user): trgm по именам полюсов + **Жаккар по объединённому lineage инстансов** (fingerprint ко-использования: «две оси объясняют один материал» — аналог «два имени претендуют на одну ячейку» WORLD) + косинус канонической строки «poleA ↔ poleB» (пара, не одиночный полюс — иначе склеятся оси с общим полюсом; калибровка отдельно от предикатов); далее регламент Р25 (кластеризация 0 LLM → judge с конкордансом инстансов → merge-миграция: union lineage, source → merged(→target), тай-брейк имени). Пороги — конфиг → ТЗ (Н8). (3) **Состав v1**: `conditions` — входит (триаж 10 §2 неполон без исхода «уточнение conditions»; симметрия с Р23; тот же проход экстракции); иерархия (`parent`, `breadth`) — v2, поля зарезервированы (потребитель в v1 отсутствует — логика П1; слепок — плоский список, salience v1 = confidence × w). Канон: `docs/concept/09` §3–§4.1 (канонизирован полностью). (сессия; Н4-остаток)

- **Р32. Аудит концепции: закрытие пяти развилок (drafts/19).** (1) **`retired` в v1** с единственным триггером **kill-insight** — явное юзер-действие, симметрия `USER_ASSERTED` (09 §4, 17 §7); автоматический retirement по затуханию — v2. (2) **`observer_id: UUID → Actor` в схеме Fact** (Р3): v1 — всегда агент сессии, фильтрация перспективы — query-параметр; `observed` в Fact не хранится — в AU observed ≡ owner (у ConstructInstance есть; поднимается при не-AU квадрантах) — 16 §2.1, 07 §5.2. (3) **Гранулярность слепка — пара `(user_id, project_id)`** + безпроектный NULL-дефолт (14 §2): CRITICAL несёт проектную часть → один слепок на юзера не собирается; глобальные секции дублируются между слепками (плата — копейки), чтение O(1) без компоновки. (4) **Инвариант чистоты уточнён** (10 §4): индукция PSYCHE читает только PSYCHE-evidence; слепок шире портрета — CRITICAL санкционированное WORLD-вкрапление (14 §2, урок NGT). (5) **PREFERENCES = селекция стабилизированных `Fact/PSYCHE`** (независимость K≥2, не поднятые в оси) — новой сущности нет, материал — те же Fact (14 §2). Редакторская часть аудита (противоречия 1.5/1.9–1.12, дубли 2.1–2.8) исполнена по корпусу без решений реестра; хвост 1.1 (исполнитель индукции) → Н6. Драфт закрыт и удалён. (сессия)

- **Р33. Исполнитель смыслового слоя: Gestalting — единственный владелец индукции (закрытие Н6).** Разводка слоёв write-path: **Dreaming (часы) — фактовый слой WORLD** (supersession, свёртка/Generalization, ко-подтверждение, лифт scope, триаж Contradiction, пост-мортем; осей не создаёт); **Gestalting (дни) — смысловой слой PSYCHE**: emerging-индукция из пула Fact/PSYCHE (не из логов — Р8), LLM-naming (Р5), переводы статусов emerging→active→drifted (гистерезис Р31), кросс-проектная PSYCHE-индукция. **Кросс-проектная индукция разведена по слоям** (10 §4): компетенсные USER-факты (WORLD) — Dreaming (ко-подтверждение + лифт); поведенческие черты (PSYCHE) — Gestalting. **Kill-insight — fast path**: мета-факт + немедленный `retired` (юзер-воля, USER_ASSERTED-природа; Р32/Р33) — переводы не ждут контура. **Триггер каденции Gestalting** — время (раз в сутки) ИЛИ объём (N новых фактов PSYCHE); N — конфиг → ТЗ (Н8). Инженерный синоним Gestalting — **«созревание»** (systems consolidation, McClelland et al. 1995; словарь 06 §8.3); «сон» закреплён за Dreaming (Р18), метафора «медленный сон» снята. Обоснования: complementary learning systems (быстрая запись ≠ медленное схемообразование — каденции совпадают), экономика токенов (часовой индуктор жёг бы LLM-вызовы и порождал axis sprawl Р31), чистота слоёв. Правки: 09 §4, 10 §4/§7, 13 §2/§6, 14 §2, 16 §6, 17 §7, 06 §8.3. (сессия)

- **Р34. Спайк до финализации ТЗ — завершён (процессное).** Вертикальный срез ядра на Java 21 (**Р17**): Ingest → Encoding (батч-экстракция + двухшаговый дедуп **Р23** + канонизаторы **Р25**) → Pure PG 16+ (таблица `facts`, 16 §2.1–2.3) → PortraitSnapshot (**Р19**: cutoff-инвалидация, джоба Reconciliation) + SQL-выражения Δопыт/w (17 §5). Вне среза: Dreaming/Gestalting (полные), прескриптивы, метрика, RLS/изоляция, WORLD-recall; read-path recall не входит (контракт **Р35** ортогонален). **Итоги (2026-09-07):** гипотезы подтверждены — Pass-Once 4 вызова LLM на 61 реплику (−93.4% вызовов, ~174 токена/реплика), дедуп 46.7% с инвариантом Р23 (смена object = событие изменения), дробление словаря без feedback-промпта (9 пар с одной сессии — патология существует), слепок O(1) (локально p95 0.47 мс; продуктовые пороги — SLA ТЗ). Итоги, дефолты и **границы валидности** — `docs/research/25` (n=1: механизмы — доказано, количественные дефолты — калибровка v0, обобщение — Р36/Р37). ADR — `docs/spec/24`; код `spike/` нетронут до архивации при переходе к разработке по ТЗ (bootstrap и каркас — CHANGELOG 2026-09-06/07).

- **Р35. Контракт запроса read-path (замечание 2.1 аудита; драфт 21 §2).** Двусмысленность Р8 снята: «0 LLM на read-path» = **движок** не вызывает LLM; формулировка запроса — обязанность потребителя. Semantic gap реплики (анафора/дейксис, разговорная форма vs нормализованное хранилище Р23/Р25) закрывается переносом в **уже идущий инференс хоста** (tool-call), не движковым LLM: ms-обещание — про подсистему памяти (слепок O(1), recall десятки мс), end-to-end всегда содержит хост-LLM. Контракт: единый `recall(query, [filters])` без режимов + детерминированная санитария движка (лемматизация, стоп-слова, entity-boost по живому словарю Р25). **Радиус recall ≠ радиус inject**: дефолт context(S) (10 §3.3), USER-радиус — явный параметр (расширение видимости — всегда явный акт; явный retrieval — не инъекция, RLS цел; кросс-проектный лифт Dreaming — про неявный контекст, остаётся собой). Структурированные фильтры (время, радиус; механика — temporal query-side Н5); возврат — Top-K фактов с провенансом (lineage 16 §2.1); multi-hop — агентная петля tool-call'ов, не движковая фича; слабый сигнал — тишина (16 §5.2). Хосты: tool (function calling — trained-in, не prompt-discipline) / inject (standing context, запрос не нужен) / пайп (тишина; детерминированное разворачивание по Messages — v2-кандидат, проверка против буквы Р8). Канонический пример — проверочный сценарий, не источник контракта (jmix-сценарий + контр-сценарии К1–К4 — 14 §6). Антипаттерны → реестр 12: безграничный LLM-пайплайн в синхронном пути (Honcho chat), двухконтрактная дисциплина search/chat. Канон: 14 §6. (сессия)

- **Р36. Детерминированные оракулы и экономика harness'а метрики.** Метрика опирается на детерминированные оракулы (must/must_not, edit-rate, veto) и статистический интеграционный тест (golden-датасет). Канон: `11 §3`.
- **Р37. Внешние бенчмарки (сравнимость + синтетика).** Адаптер read-path под внешние harness'ы (LongMemEval, BEAM) для health-отчётов (не CI-гейт) и генерации синтетики. Канон: `11 §3`.
- **Р38. Surprisal-тег.** Write-time сигнал новизны (`1 - max_sim`), вычисляемый детерминированно при кодировании, для приоритета разбора в Dreaming. Канон: `13 §2`, `16 §4.1`.
- **Р39. Регламент Dreaming.** Детальный регламент slow path (триггер, селекция кандидатов, LLM-граница, свёртка, пост-мортем). Инварианта «четыре LLM-точки» в системе. Канон: `10 §3.5`, `13 §2.1`, `16 §4.1–4.3`, `17 §8`.
- **Р40. PREFERENCES-предикат.** Стабилизация — это предикат селекции при пересборке слепка (`K>=2` независимых подтверждений), а не событие. Канон: `14 §2`.
- **Р41–Р44. Канал Correction.** Механика ручной коррекции от юзера. Включает провенанс (stated vs inferred), приоритетный supersession/пересчёт мимо каденций, hypercorrection (наследование веса), опровержение осей (kill-insight/K>=2) и форс-запуск пересборки слепка (немедленный эффект). Реплики коррекции не требуют новых LLM-инструментов и входят обычной батч-экстракцией. Канон: `06 §8.1`, `07 §5`, `09 §4`, `10 §2`, `13 §2.1`, `14 §5`.
- **Р45. ADR eval-каркаса.** Операционализация тезис-чека. Реализация интеграционного теста, разметка точек (W-требование), статистика (McNemar, асимметричные вердикты), кэширование плеча B. ADR: `docs/spec/eval/28`.
- **Р46. Инварианты целостности семантических решений.** Расширение множества предикатов контура `Reconciliation` детерминированными проверками целостности графа памяти (циклы supersession, orphan-lineage и др.) без привлечения LLM. (Закрытие Н14). Канон: `13 §3.1`.
- **Р47. Архитектурная декомпозиция — кристаллизация нити Н5.** (1) **`EmbeddingProvider` SPI** — контракт (метаданные / batch / single; single — латентно-критичный, бюджет < 50 мс), пиннинг модели на базу (`gestalt_meta`; несовпадение = отказ старта; смена модели = миграция + перекалибровка порогов Р25), реализации v1 — Remote-API (дефолт) + In-JVM ONNX (enterprise/air-gapped), fail-open (недоступность провайдера = просадка полноты, не отказ: write-path — очередь до-эмбеддинга, read-path — FTS-only). (2) **Read-path v1 = Dual-Path Tiered Assembly** (имя заявлено, 06 §8.2): standing + dynamic recall — два независимых канала (каналы и контракт поставки — канон 14); multi-signal retrieval (dense + BM25 + entity-boost, temporal query-side — фильтры, не LLM); режимы потребления inject / tool / inject+tool; v2+ — LLM-микс, агентный цикл, бюджетная лестница, пайп. (3) **Ингест: thin-shim адаптеры** — двухконтурная интеграция по хукам хоста (SessionStart / UserPromptSubmit / AssistantResponse / PostToolUse / SessionEnd; минимум — AssistantResponse + UserPromptSubmit); атрибуция Actor (07 §5 п.7: реплики PERSON/AGENT инжестятся, сырой `tool_result` — фильтр на адаптере); деплой v1 — библиотека (embed) + sidecar, hosted API — v2+ (Р11). (4) **Термины**: Dual-Path Tiered Assembly, standing context — 06 §8.2. Добор до полной декомпозиции (границы модулей, `LlmProvider` SPI, изоляция хранилищ, observability, поверхность API) — фаза ТЗ (Н8, спек 29 §5). Спек: `docs/spec/29`; поглощены драфт 29 (удалён) и парковка pre-spec 30 §2.
