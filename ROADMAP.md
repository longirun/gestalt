## Принципы

- Составы релизов выводятся из реестра решений (STATUS), не наоборот.
- Переходы между релизами — аддитивными миграциями; API не закладывает будущие сущности в пути (Р11).
- Фичи v2+ входят **по триггерам**, не по календарю (10 §6).

## v1 — ядро: портрет, который предсказывает

**Цель.** Квадрант AU (агент наблюдает человека, Р3): доказать на personal-деплое, что портрет даёт predictive lift — golden-набор L1/L2 в CI-регрессии (Р12, Р14) + онлайн-контур L3 (acceptance-rate прескриптивов). Вход в разработку — малый тезис-чек: eval-каркас `eval/` (Р45), lift > 0 на 20–50 W-точках (Р36).

**Состав (Р12):** ядро + Construct-minimal + метрика + прескриптивы.

| Слой | Содержание | Решение |
|---|---|---|
| Факт-модель | owner / domain (`WORLD`\|`PSYCHE`) / scope (`SESSION`\|`PROJECT`\|`USER`); иерархия User → Project → Session → Message; RLS по `user_id` | Р13, Р11 |
| Динамика и история | единая кривая затухания в опытном времени (несгораемый минимум; интерференционные пулы = scope); PSYCHE-статусы `emerging/active/drifted` (K = 2); история — три адресных пути, `generalized_from`, полный GIN(anchor); важность вычислима на read-path | Р27, Р28, Р29, Р30 |
| Construct | Axis + Instance; position детерминирован из evidence; lineage ≥ 2; без seed-словаря | Р5, Р31 |
| Write-path | Encoding (сек) → Dreaming (часы) → Gestalting (дни) + Reconciliation (фон); регламент Dreaming (триггер, очередь разбора, LLM-граница ≤2 батча/прогон) | Р18, Р6, Р10, Р38, Р39 |
| Хранилище | Pure PostgreSQL 16+ / pgvector; рёбра — таблицы + recursive CTE | Р7 |
| Read-path | PortraitSnapshot (CRITICAL/CONSTRUCTS/PREFERENCES, ≤40×200, cutoff, джоба ~10 мин) + WORLD-recall; 0 LLM | Р19, Р8 |
| Метрика | golden-набор (L1 выбор + L2 ответ), парный A/B lift, LLM-судья + детерминированные оракулы, ярусы harness'а — eval-каркас `eval/` + тезис-чек go/no-go; ось no-false-memory, filler-инвариант; внешний трек сравнимости (LongMemEval/BEAM) — health, не гейт | Р12, Р14, Р36, Р37, Р45 |
| Прескриптивы | минимальный канал фидбека (kill-insight + acceptance), отдельное хранилище | Р9, Р12 |
| Коррекция юзера | канал Correction — приоритетный класс write-path: `source_kind` на evidence, наследование веса (hypercorrection), форс-пересборка слепка; опровержение оси (`retired` по зрелости цели) | Р41, Р42, Р43, Р44 |
| Платформа | Java 21 LTS, zero-framework core, SPI; Apache 2.0 | Р17 |

**Явно вне v1:** workspace (Р11) · AA-квадрант (Р3, Р12) · Big-Five-проекции (Р4) · repertory-grid и полный Пиаже-цикл (Р12) · словарь канонических осей — v2+ community-реестр (Р31, 09 §2) · LLM-стратегии read-path (Н5) · дрейф-метрика (11 §5, v2+).

## v2 — экосистема: команды, сообщество, enterprise

Вход — по триггерам, не по календарю.

| Направление | Содержание | Решение |
|---|---|---|
| Workspace / мультиаренда | hosted multi-tenant SaaS, командные проекты (UU), AA-квадрант, billing/квоты — **любой** триггер; ввод аддитивной миграцией | Р11, 10 §6; AA — Р3 (07) |
| Номотетические проекции | Big Five и др. — enterprise-слой; граница монетизации = теоретическая граница | Р4 |
| Community-словарь осей | реестр канонических осей (после v1-опыта merge-дисциплины) | Р31, 09 §2 |
| Prospective memory | намерения юзера: факты с будущим valid_time или отдельная сущность | Н10(в) |
| Отложенное из Р12 | repertory-grid, полный Пиаже-цикл | Р12 |
| Портреты агентов | реестр портретов версий, политики redaction/утечка промптов | 07 (v2+) |
| Дрейф личности | метрика долгосрочной эволюции — отдельная от lift | 11 §5 |
| Динамика памяти v2 | непрерывная интерференция полюсов, `retired`-статус конструкта, точная единица опытного времени | Р27 |

## v3 — платформа (белое пятно)

Определённого состава v3 в реестре решений **нет**; единственные маркеры — workspace-триггеры масштаба «AA-портреты в собственности тенанта» и «billing/квоты как граница» (10 §6). Роль v3 в роадмапе — резерв под триггеры v2, сработавшие на масштабе. Честная фиксация: состав v3 не определён; наполнение — решениями (РNN) по мере эксплуатации v2.
